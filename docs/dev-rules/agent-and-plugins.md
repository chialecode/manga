# Agent、上下文与插件开发规则

触发：工具/schema、prompt、上下文、模型路由、模块启停、装配或插件兼容变化。字段和状态机正本见 [Agent 协议](../design/agent-and-plugins.md)及 [组合方案](../design/composable-ai-native-architecture.md)。本文件管理 MANGA 产品实现，不改变编程 Agent 当前任务的授权。

## 必须落实的边界

| 范围 | 实施要求 | 验证 |
| --- | --- | --- |
| 工具 | UI 与 Agent 共享命令；每次调用校验当前能力、权限、目标版本与幂等键 | AT-09—11、AT-44 |
| 上下文 | 发送时固定目标/来源/版本；临时状态有时间和新鲜度；先过滤权限/项目/进度再提取 | AT-10、AT-11、AT-24 |
| 模型结果 | 候选经 schema 和业务校验后才可写入；资料与指令分离 | AT-11、AT-12、AT-29 |
| 成本和失败 | 预算、步骤、时间、重试有界；保留中间产物，取消状态由执行器确认 | AT-08、AT-13 |
| 路由 | 按任务能力选择模型；回退仅使用已有授权路由；用量估算不冒充实际账单 | AT-12、AT-31 |
| 插件清单 | 静态声明与实际贡献一致，硬/软依赖与 single/many 绑定明确 | AT-14、AT-36 |
| 生命周期 | 资源归作用域；激活失败清理；停用阻止新调用、排空提交、拒绝旧 epoch | AT-14、AT-37、AT-48 |
| 用户意图 | 显式关闭优先；隐藏、停用、卸载和数据清理语义独立 | AT-38、AT-42 |
| 不可信执行 | trustClass 由宿主实际边界确定；进程、vm、清单或签名不是完整隔离证明 | AT-34、AT-45、AT-47 |

工具/上下文改动同时更新能力描述、应用服务、错误、可发现性、作者说明与场景样本。模块晚到任务只能形成协议允许的可恢复产物，不可继续写入新焦点对象。Agent 运行时和组合内核各自可替换，不将模型 SDK 类型泄漏到领域协议。

## Prompt 与模型验证

确定性权限、版本保护、范围过滤和状态机由代码落实，不能只加一句提示词。prompt 改动注明触发场景、希望改变的行为和固定评估样本；先用可控模型/提供者验证协议和错误，再按授权做有限真实服务测试。

模型语义质量单独核对来源支持度、任务完成情况和待核实内容，不以一次回答或 API 成功当作全面通过。普通 prompt 修订不自动产生新的审批要求；若确实扩大产品行为、网络材料范围或副作用，再按需求和决定流程处理。

## 插件升级与作者契约

升级同时核对 manifest/API、配置、权限、对象 schema、安装资产与用户状态。新增权限不能静默生效，已有配置和用户数据须迁移；代码回退遇到新数据格式按只读/兼容恢复处理。实现 SDK 时维护可运行的最小插件例子和失败场景，示例能否运行以执行报告为准。

M1 的可信内置/开发插件与 M4 的第三方执行范围分别验收。停用后的未知数据和引用导出能力不依赖重新联网安装模块。
