## 1. 阶段判断

本轮复核和局部修复可以收尾。不能把 Cursor 的 R0—R7 自述、当前测试全绿或 `engineeringReviewable: true` 理解为 M0 整体通过。当前正式技术栈已按 ADR-0007 确认，但实际原型仍使用 textarea、node:sqlite、Zod 3、实验构建。有限资源授权、实际 UI 生命周期、新驱动与恢复、格式和设备的关键验证尚不完整。

按照[路线与验收](../delivery/roadmap-and-acceptance.md)，可以连续推进 M1a 所需的基础验证和 Agent 实现；先完成安全、生命周期、存储与新栈打包门槛，再交付产品。完整阅读/编辑与录音归 M1b，目标视频/漫画与 Bangumi 归 M2，BitTorrent 和第三方执行隔离归 M4。阶段划分不撤销 M0 未完成项，也不把旧的格式拒绝结果变成产品范围决定。

下一轮已有[详细执行计划](../delivery/m1a-execution-plan.md)和[完整 Cursor prompt](../delivery/m1a-cursor-prompt.md)。目前没有需要用户先回答才能继续本地基础实施的新决定。运行时与写入宿主的正式定稿，应在开发者补齐具体证据、维护成本和推荐后集中提交。

## 2. 本轮发现与修复

新增 `closure-review.test.ts` 的 6 个回归用例中，前 5 个在修复前复现失败；不是只对实现形状做断言。资料包当前对普通错误具备回滚保护，但“文件发布后、事务提交前进程退出”仍可能留下孤立文件并导致重试拒绝；不能把异常捕获测试提升为断电恢复证明。真实用户资料迁移前必须先完成 P2。

## 4. 性能结果与测量限制

按 A-14 使用当前 Windows 11 电脑作首轮参考机，未恢复旧的 4 核/16 GiB 要求，未放宽响应目标。[原始数据](m0-final-review/bench.json)保留样本与计时方法。

| 测量 | 结果 | 目标 / 样本与口径 |
| --- | --- | --- |
| 服务检索 | p95 0.0815 ms | ≤500 ms；100 次查询，10,000 资源/50,000 检索块，不包含 UI |
| 输入 DOM 状态回执 | p95 0.2 ms | ≤100 ms；100 次输入，不含显示合成/显示器延迟 |
| 新进程启动 | p95 469 ms；最大 472 ms | ≤5,000 ms；30 次，未清 OS 磁盘缓存 |

| 上下文 | p95 15.9372 ms | ≤150 ms；30 次 |
| 10 MiB TXT 获取并截取首屏 | p95 36.0638 ms | ≤2,000 ms；30 次，预览仅 8,000 字符，不证明全文交互 |

全部已测子集达到原目标，不能宣称需求 6.2 全部通过。EPUB 夹具仅 1,615 字节，30 MiB EPUB 首屏未测；输入真实绘制延迟、真实麦克风启动、正式 React/存储栈性能待对应阶段。后续新栈需重新测量，不能沿用本原型数字。
