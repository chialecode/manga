## 1. 产品定位与价值

MANGA 是一个本地优先、Agent 原生参与的二次元内容工作台。产品主线为：

> 围绕二次元内容，让阅读观看、随手记录、素材整理和辅助创作形成连续的工作流。

用户应当能够在阅读小说、漫画或观看动画时捕捉想法，将带有来源位置的记录复用为创作材料，并让 Agent 在明确的内容与项目范围内协助整理和产出。

核心价值由以下可验证行为体现：

1. 记录发生时保存内容位置，后续可以准确返回来源。
2. 一份材料可以被多个视图和项目引用，保持来源关系。
3. Agent 通过结构化状态理解任务，并调用与界面相同的业务能力。
4. 用户可以关闭 AI 或停用某个功能，数据保持可恢复、可导出。
5. 功能模块能够在另一个宿主中独立运行，为拆分应用提供基础。
6. 下载能力可以后装，外部动漫数据库可以替换或按字段组合，本地收藏、文件和引用不被外部服务绑定。

组合机制见[可组合与 AI-Native 架构](../design/composable-ai-native-architecture.md)。元数据首批接入 Bangumi，下载首批采用 BitTorrent；具体引擎在对应阶段选择。

首版平台与账户基线已于 2026-09-19 确认：本地单用户、基础功能无需登录、Windows 11 x64 首发；其他桌面系统后续独立验收。安装形式等未决事项按台账处理；基础技术按 [ADR-0007](../decisions/0007-technology-stack.md)实施。

## 2. 用户、工作区与工作范围

### 2.1 用户类型

| 用户 | 主要目标 | 高频场景 |
| --- | --- | --- |
| 爱好者 | 管理与消费本地二次元内容，保存感想 | 续读续看、查找作品、划线、语音记录、询问当前内容 |
| 内容创作者 | 将资料和想法组织为作品 | 素材收集、人物与设定整理、提纲、文案、片段拼接 |
| 同时具有两种身份的用户 | 将消费过程积累的材料自然转为创作输入 | 看完一集后，把感想和片段加入某篇评论或视频脚本 |

### 2.2 一个工作区，按项目组织

2026-10-22 起不再分两种模式（A-94，取代此前的“观测者 / 造物主”与“娱乐 / 工作”两种模式）。所有功能都在同一个工作区里：

- **项目与“最近”。** 工作按项目组织；只是看番、读书、随便问问时，对话和打开的资源放在“最近”里，随时可以加入项目。项目和“最近”各自记住自己的标签、布局、对话与阅读观看进度（A-95、A-96）。
- **标签页与分屏。** 资源库、阅读器、项目里的对象、对话和设置都在主区以标签打开；主区可以分成左右两栏、三栏或四宫格，创作时可以一边看原作一边写（A-95）。
- **同一个文件。** 不同项目可以同时打开同一个文件，各在自己的标签里，进度各记各的。
- **能力不随位置改变。** 资源、笔记与引用全部共享；项目里的对话可以使用本项目的创作命令，项目之外的对话不能（A-73、A-94）。
- 功能开关单独管理。隐藏一个入口不会自动停用其后台能力。

内部的模式值（`enthusiast` / `creator`）只在升级迁移里读取：两种模式下已有的对话、已打开的资源与布局迁入新的工作区，不丢弃（迁移见当前阶段计划）。

界面评审阶段曾增加清楚标注的动画演示页（静帧、模拟时间轴、演示字幕/分集/标记、内存笔记及预设示例对话），它不导入真实视频、不创建业务资源或 Agent 任务；该演示页已被真实播放器取代，正式播放、字幕解析与逐帧按 AT-23、AT-53、AT-69、AT-71 验收。

### 2.3 个人资源库与项目

个人资源库管理作品、版本、本地资源、进度与个人记录。项目管理一项创作任务的目标、材料集合、项目对象、术语与 Agent 会话。

一个资源可以被多个项目引用。笔记等创作对象有一个明确的所属范围，其他项目通过引用复用。Agent 默认使用当前任务允许的项目材料；跨项目材料需要被显式加入任务范围。

## 3. 核心用户旅程

### 3.1 阅读并记录

导入小说 → 调整阅读样式 → 选中一段文字 → 输入或说出想法 → 生成带引用的笔记 → 重启应用后继续阅读 → 从笔记返回原文。

成功条件：字体、窗口和文件位置变化后，引用仍可恢复或给出明确的修复入口。

### 3.2 观看时口述感想

打开动画 → 播放到某个场景 → 主动开始录音 → 继续观看或暂停 → 转写与整理 → 查看关联时间 → 点击笔记返回对应片段。

成功条件：笔记位置由录音当时的内容状态决定；异步识别延迟、倍速和跳转得到正确处理。

### 3.3 把记录变成创作材料

选择个人记录 → 加入项目 → 拖入白板 → 与人物设定关联 → 放入思维导图提纲 → 生成文案草稿 → 查看依据并修改。

成功条件：同一材料保持可识别的身份，引用可追溯，编辑与复制语义清晰。

### 3.4 Agent 跨页面协作

用户选中材料 → 查看 Agent 将使用的上下文 → 提出任务 → Agent 检索授权材料并调用工具 → 展示草稿或变更结果 → 用户继续编辑或撤销。

成功条件：任务固定目标与版本；切换页面不会将结果误写到新页面。

### 3.5 以引用片段组成粗剪

收藏动画时间范围 → 加入粗剪项目 → 排序与预览 → 检查实际可导出的切点与兼容性 → 导出新文件。

成功条件：保留来源与请求区间，导出结果明确标注实际区间，原始素材保持完整。

## 4. 范围与交付原则

产品按 Agent 优先交付：先建立 Agent 主页面、OpenAI 格式文本/转录接口、连接设置、首次配置和资源总览，再接入小说、笔记与录音完整流程，然后扩展漫画与动画，最后是创作组织、限定范围的粗剪、插件分发与 BitTorrent 获取。已实现与待实现的范围见[执行状态](../delivery/status.md)与[交付路线](../delivery/roadmap-and-acceptance.md)。

A-39 明确软件整体先形成包含上述全部基本功能的 MVP，再根据反馈循环迭代。各能力的验收用例是完整验收边界，不是必须把一个模块打磨到所有余项清零才可开发下一个模块。MVP 基础链路及延期规则只在[交付路线](../delivery/roadmap-and-acceptance.md#mvp-loop)维护；已确认格式、来源、权限和恢复要求不因 MVP 而静默撤销。非阻塞问题进入统一台账和后续 loop，基本流程与数据正确性问题优先关闭。

基础模型、引用、命令、模块生命周期和导出协议先于业务功能建立。后续功能接入既有协议，并根据验证结果调整模型。

A-40 将全项目技术方向调整为活跃开源优先：A 制定技术方案前查证可用且维护中的方案，默认围绕适配和组合设计，而非重复实现通用引擎。MANGA 保持领域身份、引用、权限、恢复和跨模块语义的所有权；技术选择与升级通过实际场景验证。具体流程见[选型规则](../dev-rules/architecture-and-contracts.md#open-source-first)，不是对尚未验证候选的自动采用。

以下暂不进入当前范围：实时多人协作、云账户与同步服务、复杂视频特效与任意格式转码、未获授权的内容下载、DRM 解锁、全系统自动听写、游戏平台或游戏运行引擎。Game 的具体产品需求在 vNext 单独定义。

### 5.1 产品基础

| 编号 | 必须具备的行为 | 状态 |

### 5.2 资源库与进度

| 编号 | 必须具备的行为 | 状态 |
| --- | --- | --- |
| LIB-01 | 资源库的内容以设置里的资源库位置为准（A-69）：按媒介添加资源库位置，扫描登记位置下的文件，不复制、不移动原文件；没有可以挑选任意文件的独立“导入”。后台按间隔自动增量扫描，显示阶段、数量与当前项进度，可取消；扫描期间界面保持响应；支持进度、取消、错误报告和重复资源识别；文件消失只标为不可用。导入只做轻量探测：视频只读容器信息与抽样指纹，逐帧时间表在第一次逐帧操作时才在后台低优先级建，一次只建一个，时间输入不等它（A-72）。以前单独导入、不在任何位置下的资源保留，标为库外资源并提示把所在文件夹加为资源库位置；下载完成的文件所在目录是资源库位置。资源的位置是“资源库位置 + 相对路径”（A-80）：读取资源文件只经一个解析函数，库外的文件不能读、不能导入，“重新定位…”只接受资源库位置下的文件（文件选择器默认打开该位置，选到库外时提示先把文件夹加为资源库位置），也只认同样内容的文件；资料包恢复时媒体写进用户选的资源库位置或不恢复媒体。资源库位置可以“更改路径”：抽样核对新路径下的指纹一致后只改位置记录，资源、进度与用户内容全部保留。库外资源不能打开阅读，作品主页与“资源不可用”视图仍列出它的笔记、书签、录音与对话，并提供“把所在文件夹加为资源库位置”。只能打开资源库里的、文件在的资源（A-86）：每个打开与取内容的命令（读取、取页、视频的播放与副本、字幕、字体、帧表、材料帧与区域、截图保存、弹幕匹配的文件指纹）先做同一个检查（`library.openable` 用的函数），库外与文件丢失分别以 `LOCATION_UNAVAILABLE` 拒绝并带原因，有播放副本的视频同样不能播放，Agent 的读取经过同样的命令；界面在打开前先问，所有入口（书架、总览、作品主页、左栏“已打开”、继续、来源跳转、对话绑定的资源、模式切换与后退前进）都经过同一个入口，不能打开时不进阅读器、不改页面，弹出提示：库外的写明所在文件夹，可以“把所在文件夹加为资源库位置”，文件丢失的可以“重新定位…”，两种都可以“查看笔记与记录”；重启后的恢复遇到不能打开的资源，停在原来的列表页、不弹窗；资源所在的资源库位置被移除时，已发出的媒体句柄作废，打开着的阅读器关闭并提示，左栏“已打开”里去掉它，会话与进度保留；书架与总览照常列出这些作品，用户内容找得到 | 已实现 |
| LIB-02 | 按作品、版本、卷章或集组织资源；支持封面、别名、语言、标签、收藏、书架状态（想读/在读/已读/搁置）和手动修正；保留元数据来源。每部作品有主页，展示资料、卷/话/集、角色与制作人员、记录与相关作品，并从“阅读/观看”打开文件；全部资料字段（包括空字段）可手动编辑。总览与三个资源库以作品为单位：已关联同一 Bangumi 条目、同一媒介的作品显示为一个入口，组内每个作品是一个资源版本，阅读或观看时选择版本，默认上次的版本，换版本时同一集或同一卷尽量保持位置；没有关联的作品各自显示，取消关联即拆开（A-68，Q-25：只合并显示，不合并数据）。用户创作的内容（对话、笔记、书签、录音、术语与词典）不随资源的可用性消失：不可用的资源仍能打开“资源不可用”视图，列出这些内容并提供重新定位，同指纹的文件再出现时自动重新关联，作品清空后保留为没有资源的作品，只有用户明确删除才删除（A-67）。总览与三个媒介页的卡片菜单、作品主页的“更多”有“删除条目…”（A-87）：一个入口是一组版本时删除整组；确认弹窗分别列出会删除的（作品记录、在线资料的关联、快照、候选、改过的字段、封面选择、没有其他作品用到的角色与制作人员、书架状态、版本分组、只由在线资料推出的弹幕匹配）与会保留的（资源与文件、进度、书签、笔记、录音与转写、截图、对话、用户确认过的弹幕匹配、词典与术语）并写明数量与“不能撤销；文件不会删除，仍在资源库里”；删除后资源成为“未归入作品”的资源，书架与总览的末尾有一组“未归入作品”，可以打开、“归入作品…”或“匹配条目…”，扫描与导入不会自动把它们重新分组；只挂在作品上的内容（作品级的笔记、作品会话、作品词典）带着删除前的标题，在笔记管理标签与词典里找得到；写操作日志 | 已实现 |
| LIB-04 | 提供专门的资源总览页，汇总资源、工程、笔记、剪辑、录音及存储位置/占用/可用状态；按类别筛选并进入管理或修复 | 已实现 |
| LIB-03 | 记录最后位置、已消费区间和完成状态；支持续读续看、重置、手动标记与历史查看；不同版本和改编作品的进度分别保存。进度按项目分开（A-96）：每个项目与“最近”各记各的最后位置、已消费区间与完成状态，互不影响；资源库的卡片显示最近一次的进度，并注明来自哪个项目 | 已实现 |

导入不以文件路径作为资源身份。移除资源库条目与删除磁盘文件是两个明确操作；默认移除只改变资源库关系。已被引用的资源移除后，保留引用记录并提供重新定位入口。

元数据可以逐步补充。联网补全采用可选连接器，只在用户对某部作品发起匹配或刷新时联网，展示来源，允许用户保留自己的修改；不做自动匹配和自动同步（A-51）。

封面（A-44、A-51）：资源页显示作品封面。封面默认从文件本身提取；也可经元数据连接器（首批 Bangumi）在用户确认关联后下载。网络同步的资料与封面原图、用户指定的封面图保存在本地数据库中，断网或停用连接器后仍可显示；从文件提取的封面与缩略图是可重建缓存。用户可替换、锁定封面。

### 5.3 阅读与播放

| 编号 | 必须具备的行为 | 状态 |
| --- | --- | --- |

| UI-10 | 工作上下文（A-94、A-96）：每个项目与“最近”是一个工作上下文，有自己的标签与布局、对话和阅读观看进度；同一个文件可以在几个上下文里同时打开；在项目里打开的资源、写的笔记、录音和截图加入该项目的材料（Q-33）；右侧停靠栏的对话跟随获得焦点的标签；升级时两种模式下的对话、已打开的资源与布局迁入新的工作区，不丢失 | 已实现 |
| DATA-04 | 资源、工程及安装目录外全部应用生成内容的位置可由用户配置，默认系统文档目录；开发版/正式版使用独立路径与凭据命名空间；迁移可验证、失败可恢复 | 已实现 |
| DATA-05 | 作品内容文件夹（A-79）：用户为一部作品产出的内容放在位置分区 `works` 的同一个文件夹里，结构按条目与文件分（A-88，取代 A-79 里的结构）：资源所在的作品关联了条目（Bangumi）时是 `<媒介>/<条目名>/`，同一条目、同一媒介的资源共用（A-68）；没有关联条目的资源是 `未分类/<资源文件名>/`，每个资源文件一个，条目被删除或取消关联后也一样；只挂在作品上、没有资源的文件在条目的文件夹，没有条目时在 `未分类/<作品名>/`。文件夹名在创建时确定，重名时先加上级文件夹名、再加序号，作品改名时不跟着改，可以手动“按当前标题重命名”。子文件夹是 `截图`、`录音`、`粗剪`、`导出`、`笔记`；录音、导入转写的音频（“导入录音文件”会先复制进来）、粗剪导出与截图写在这里，数据库的 `work_files` 记录其中的内容。笔记也写成文件（Q-31，单向）：属于某个资源或作品的每条笔记在 `笔记` 里有一个 Markdown 文件（由 `mdast-util-to-markdown` 生成），开头写来源（作品、资源、位置）并注明“由 MANGA 生成，在这里修改不会写回应用”，保存后写入、连续保存合并成一次，改标题时改名，删除笔记时删文件、恢复时重写，嵌入的截图在同一文件夹的 `截图/` 里时写成相对链接、否则写成文字说明；既没有资源也没有作品的笔记（全局笔记、项目笔记）不写；数据库仍是笔记、书签与对话的正本。关联、取消关联、删除条目、归入作品时文件按规则移动，不覆盖同名文件，记进 `file_moves` 日志，可中断后重做；位置在设置的位置页配置，迁移位置时随之移动，不能与资源库位置重叠；已有的文件与笔记在升级后的第一次启动时按新规则重排，在后台进行，可中断后重做、不重复，已有录音在升级时迁移进来 | 已实现 |
| DATA-01 | 本地持久化、事务、明确的保存状态、崩溃恢复和版本冲突处理；进度与笔记自动保存 | 已实现 |
| DATA-02 | 提供备份、恢复、资源重定位、存储用量与缓存重建；备份包含所有业务数据，不包含明文凭据。设置中的“日志”记录关键操作（谁、何时、对什么、结果），可筛选，不记录凭据与内容正文 | 已实现 |
| DATA-03 | 可导出笔记与结构化引用；项目包保存必要对象、来源与版本，媒体可选择附带；支持往返导入和冲突处理 | 已实现 |

### 6.2 初始性能目标

以下为设计目标。阶段门禁记录实际机器、资源样本与测量方法；远程模型延迟不计入本地响应指标。

首轮参考环境：经确认的 Windows 11 x64 环境、单主窗口。保留下表响应时间目标，公开报告记录平台、构建版本和测量方法，设备明细留在本地脱敏前记录；10,000 条资源元数据、50,000 个可检索文本块；测试用媒体来自支持矩阵。结果仅适用于被测机器，不外推最低配置。

| 项目 | 初始目标与口径 |
| --- | --- |
| 本地界面反馈 | 常用按钮、输入与任务启动反馈 p95 ≤ 100 ms，不含任务本身完成时间 |
| 已加载页面的轻量上下文查询 | p95 ≤ 150 ms；返回位置与选区元数据，全文/OCR 另行异步请求 |
| 本地全文搜索 | 索引就绪时前 20 条结果 p95 ≤ 500 ms |
| 冷启动至可操作资源库 | 在基准库规模下 ≤ 5 s |
| 已索引小说首屏 | TXT ≤ 10 MiB、EPUB ≤ 30 MiB 样本上 p95 ≤ 2 s；重解析单独报告 |
| 录音状态反馈 | 开始或停止请求后 ≤ 300 ms 内展示真实状态或设备错误 |
| 自动保存 | 编辑草稿目标 ≤ 1 s；连续阅读/播放进度目标 ≤ 2 s，暂停/跳转/关闭时立即提交 |

应用必须区分“正在保存”和“已保存”。异常退出前尚未得到持久化确认的瞬时状态不承诺零丢失，但应恢复最后已提交状态。

### 6.3 内容与数据正确性

- 来源定位使用资源 ID 与版本，位置恢复包含校验和明确的失败状态。
- AI 生成内容记录输入来源、配置模型和生成时间，不能将生成摘要标记为原文。
- 已消费范围由实际消费事件或用户显式标记形成，跳转经过的内容不会自动全部计入已读。
- 嵌入模型或分段规则变化后旧索引不可混用，重建期间全文搜索继续可用。
- 用户录音、笔记和项目属于原始业务数据；封面缩略图、OCR 索引等可再生内容分别管理。

## 7. 典型异常及预期产品行为

| 异常 | 预期行为 |
| --- | --- |
| 资源移动、改名或磁盘离线 | 保留条目与引用，提示定位资源；根据内容校验恢复，不能静默链接到同名文件 |
| 原文或视频被替换 | 创建或识别新版本，校验锚点；无法可靠映射时由用户修复 |
| 没有 API key、模型能力不匹配 | 展示所缺能力；本地阅读、人工记录与已有内容可用 |
| 转写成功、整理失败 | 保留转写原文与位置，允许稍后整理 |
| Agent 生成期间用户编辑目标 | 按版本冲突处理，保留建议稿，允许比较与合并 |
| 正在使用的模块被停用 | 提示受影响功能，按停用流程处理任务并释放资源，数据保留 |
| 嵌入目标存在循环或模块不可用 | 展示可跳转的引用卡片或预览，不无限展开 |
| 无转码导出不兼容 | 报告具体不兼容项，保留编辑项目，不悄悄切换为高成本转码 |

## 8. 产品效果与验收方式

产品效果通过本地场景验证与用户测试观察，不默认上报内容或行为遥测。

- 能否从阅读/观看自然创建记录，且不丢失位置。
- 能否从记录返回原文、画面或片段。
- 能否将同一材料复用于多个创作视图。
- Agent 结果是否有依据，操作是否发生在正确目标上。
- 停用模块、切换模型、断网和资源迁移后是否仍能继续工作。

每项需求的测试入口、阶段门槛与用例映射见[交付阶段与验收计划](../delivery/roadmap-and-acceptance.md)。完成一个页面或一个按钮不等于完成对应需求，必须通过其完整流程和关键异常验收。
