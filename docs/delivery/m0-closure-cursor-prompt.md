二、立即优先修复回放问题（R1）

用户报告进度条偶发异常，原生“三个点”下载入口时有时无。已有只读合成诊断：MediaRecorder WebM 初次加载 duration=Infinity，播放完才得到 1.14 秒；ffprobe 也未读到容器/流时长。见 docs/evidence/m0-review/audio-playback-diagnostic.json。这不是用户真实录音，不能断言涵盖其所有异常。

当前 renderer.js 的 refresh() 会 replaceChildren 重建录音列表，笔记自动保存也会调用，因此可能销毁正在播放的 audio；反复点击又新建 audio，Blob URL 没释放；没有独立导出按钮。

请修复有限时长/实际 seek、一致的进度显示、回放元素和状态保持、乱序加载及 Blob URL 生命周期，增加稳定可见且键盘可达的“导出录音”。导出通过受控主进程接口和保存对话框，校验附件归属、处理取消/冲突/权限错误，不能暴露 renderer 任意路径写入。保存重试保持同一次录音幂等，旧缺时长 WebM 保留兼容且不覆盖原音频。

用实际录音→保存→重启→读取→播放→导出链路回归，覆盖初次播放前拖动、播放结束后重播、较长录音、回放中笔记自动保存、连点多录音、导出取消/失败、窄窗/三档缩放。不要仅设置一个假的 duration 或只检查按钮存在。
