## 1. 起点与交付目标

从现有任务分支、工作区和 [本轮复核结果](../evidence/2026-09-19-m0-closure-review.md)继续。当前可用的是修复后的 M0 实验程序：textarea、node:sqlite、Zod 3、实验构建；React、better-sqlite3/Drizzle、Zod 4、Vite/Forge 尚未集成。不得重新建空仓、删除既有实现、重建用户库或把原型成绩直接继承给新栈。

版本交接按 [Git 工作节奏](../dev-rules/git-and-github.md#1-本地优先与工作节奏)：先检查是否已有 M0 复核基线提交，未保存则在有效授权内核对范围并保存；不要重复提交相同基线。随后以明确基点建立一个 M1a 目标分支，前置未合并时登记依赖。P0—P5 在同一分支连续完成、自检后形成一个首次交付 commit；后续同一交付未 push 的集中审查修复 amend 原提交，消息描述最终结果；已推送后默认追加集中修复。M0 与 M1a 是不同交付，即使都未 push 也分别保留 commit。内部工作包是实施和验证边界，不要求逐包提交或建分支。中间仅按大改造回退、试验分叉或中断恢复需要保存检查点；审查收敛后按有效授权集中 push，PR/合并/发布的授权分别判断。

开工 Git 步骤由执行 Agent 一次衔接，不要求用户逐步指挥：

1. 检查当前分支、工作区及最近提交。若 M0 基线已保存，复用其提交；若仍在 `feat/m0-tech-contract-validation` 且留有本次复核成果，先核对归属、验证并形成一个基线 commit，保留 M0 未整体验收的真实说明。
2. 准备 `feat/m1a-agent-foundation`。当前已在该分支且继承正确基线时直接继续；分支不存在时从已保存的基线创建；已存在则核对其依赖与已有工作，不重置或覆盖。M0 未合并时记录它是前置分支，不能改从缺少 M0 代码的旧 main 开工。
3. 完成或识别上述准备后直接进入 P0，不为 commit、建分支或开始下一工作包再次询问。M0 的 push/PR/合并不是本地开工前置；仅按已有授权执行或放入最终待批清单。

本轮完成可独立运行的 M1a Windows 本地产物：中文 Agent 主页面、共享会话副驾驶、OpenAI 格式文本/文件转录连接设置、可跳过 AI 的首次配置、全部生成内容位置配置与恢复、资源总览。Agent 和 UI 调用相同的已交付业务服务。使用本地可控提供者即可完成协议与故障验收，真实兼容端点另做少量人工契约确认。

工作顺序为 P0 → P1 → P2 → P3 → P4 → P5。开发者完成每个工作包的检查后连续推进；P1/P2 的权限、存储与恢复门槛必须在开放真实 Agent 工具前通过。M0 整体退出继续单独记录；本计划不撤销其未完成验证，也不把后续产品阶段改名为 M0 完成。

按照 A-20 和[连续执行流程](../dev-rules/development-workflow.md#continuous-execution)，工作包完成是技术检查点，不是逐包人工审批。Agent 自主处理范围内实现、常规依赖、失败修复与文档更新；原型视觉和技术候选先形成可审阅实证。非阻塞决定、真实服务/设备配置和所需外部操作授权统一列入最终交付，只在真实阻塞且不能隔离时提前询问受影响部分。

本轮角色按 [A 规划 → B 执行 → A 审查](../dev-rules/development-workflow.md#agent-handoff)：本计划为 A 给 B 的唯一详细任务入口，Cursor 承担 B 的连续实施和自审，交付后由 A 集中复核。B 在 `docs/evidence/m1a-delivery.md` 提供[交接模板](../templates/agent-handoff.md)所需信息，逐项映射 P0—P5/相关用例到实现和真实验证；同步登记与导航。报告已存在时更新本轮范围并保留历史证据，不能覆盖旧结果伪造通过。A 直接修局部问题，较大缺口以稳定编号一次性反馈，B 仅补差异，不重启整份任务。

## 2. 工作包、依赖与完成证据

### P0：正式工程与已有修复接续

1. 按 AGENTS 检查分支、工作区和有效决定。按仓库地图建立有实际使用方的产品宿主与模块，保留实验基线和回归场景。新模块补规格，记录数据所有权、命令、上下文、停用和导出。
2. 建立 React/React DOM、Vite、Electron Forge/plugin-vite；实际组件按需使用 Radix、Tailwind、Lucide，消息展示使用已选 Markdown 方案。集中中文文案、语义 Token、错误和可访问性状态。
3. 接入 Zod 4 并验证原 Zod 3 契约的调用兼容。新测试使用 Vitest/Testing Library，浏览器/Electron 烟测使用 playwright-core；在场景覆盖迁移之前继续运行现有 node:test，不能删除失败场景来完成迁移。
4. 保留本轮已修复语义：指定资源修订、Unicode 码点选区、单块修改、资料包范围/哈希/失败回滚、采集跳转后时间推进、停用后旧结果拒绝、回放原始字节与独立导出。

完成证据：实际开发命令、类型检查、依赖边界、React 首屏、中文输入的合成组合事件、独立本地产物可启动。React 原生输入法留到最终界面稳定后短测。Tiptap/CodeMirror、sharp/ws 等没有本轮使用方时不提前安装。

### P1：真实权限与生命周期门槛

1. 将实验中固定字符串 `scopeHandle="library"` 升级为可信宿主发放的有限授权。至少绑定 actor、任务/会话、允许命令、读写对象或资源集合、模块代次和撤销状态；模型参数不能设置这些可信字段。路径选择产生宿主句柄，不能让模型填写任意磁盘路径获得访问权。
2. 范围校验覆盖查询、上下文、检索、写入和导出。过滤发生在返回正文之前；空允许集不能退化为全库；幂等回放同样重新核对当前调用者授权。用户、Agent、工作流共用业务语义但不共享无限授权。
3. 将 React UI Facet、命令、上下文提供器和解析 worker 接入真实启停链。停用撤销入口/工具/上下文、取消任务、阻止旧 epoch 提交；重新启用恢复新 worker，用户数据保留。用受控屏障复现竞态，不用“成功或失败都算通过”的断言。
4. 验证重复释放、激活失败、50 次启停、IPC 取消/退出/丢序重取快照、依赖替换和上次有效装配恢复。复杂图变更或原生组件替换可要求重启，界面准确显示期望与实际状态。
5. 对 ADR-0004 写入宿主和 ADR-0005 运行时提供具体技术建议：必要契约、已测证据、维护责任、兼容/诊断成本、热变更边界。当前 kernel 可继续作为隔离候选；MinimalActivator 只作失败反例。若无需第二个完整候选，说明依据，不虚构公平比较。未获决定前不代签 accepted。

完成证据：POC-04/07 对应 M1a 子范围、AT-11/14/36/37/44/48 的相关场景；至少展示一个实际跨资源越权被拒绝、一个晚到写入被阻止、一次 UI 与 Agent 共用命令的完整流程。可信内置模块验证不等于第三方安全沙箱。

### P2：新存储、位置配置与恢复门槛

1. 将持久化适配到 better-sqlite3 + Drizzle + FTS5，保持公共 DTO 不暴露 ORM 类型。一个 Profile 一个写入宿主作为待验证候选，验证并发启动冲突、事务/事件/幂等、取消与提交边界。
2. 使用合成的现有版本数据库和资料包，验证旧库打开、升级成功/失败、版本过新拒绝或恢复入口、身份/修订/锚点/进度/未知对象/附件保持、中日文检索与范围过滤。备份和“可移植资料包”范围分别说明，后者不是现有整个 Profile 的等价备份。
3. 补资料包和位置迁移的进程中断恢复：复制、校验、文件发布、数据库提交、配置切换分别注入真实子进程退出。中断后可识别本次暂存/孤立文件、恢复或回滚；不得把异常捕获回滚当作断电恢复证明。保留原始文件与冲突文件，不自动覆盖非空目标。
4. 按 DATA-04 覆盖全部非安装内容：数据库/配置、托管资源、工程、附件/录音、下载/暂存、缓存/索引、日志/崩溃转储、备份、导出、运行时资产。默认由平台解析系统 Documents 下的 release/development 子树；测试单独隔离。开发/正式路径和凭据命名空间独立。
5. 明确启动定位机制，在 Electron 初始化写入前配置 userData/sessionData 等位置。启动参数/环境配置可定位 Profile；持久化指针的位置也必须可配置并在设置展示。Documents 重定向、离线、不可写时有选目录/重试/恢复入口，不悄悄回落到另一固定目录。
6. 设置变更先生成可审阅的迁移范围和检查点，暂停相关写入，校验复制后再切换配置；失败保留旧位置、ID 和回退入口。仅索引的外部原件不随默认根移动。所有自动测试只迁移合成 Profile，不迁移用户真实数据。
7. 接入 safeStorage 适配器；配置只保存 credentialRef。应用持有的密文位于已配置 Profile，密钥不进入状态快照、日志、工具参数或资料包。保护机制不可用时显示真实错误，不静默明文落盘。

完成证据：POC-06 新驱动、AT-17/18/21/35/48/51 的本轮相关范围；实际 Windows 原生 ABI/rebuild/asar 检查、独立包启动/重启/恢复、新旧数据往返和故障日志。不得把 node:sqlite 原型或单次 SQL 查询作为新栈证明。

### P3：模型连接与有界 Agent 服务

1. 按 A-22 接入自研与 PI 两种服务端 AI runtime，设置可持久切换且运行开始后固定选择，领域协议不依赖具体 SDK。分别实现 Responses 与 Chat Completions 的文本、流式内容/工具参数、完成与错误事件；SDK 未覆盖的接口通过独立协议适配器补齐。领域层不暴露供应商消息结构。
2. 独立实现 audio/transcriptions multipart 文件上传，支持独立 LLM/ASR 连接和对应类型的模型，并明确 Embedding 的独立配置契约；向量索引按 SEARCH-02 后续交付。音频只能发给 ASR，ASR 未配置则本地拒绝、不上传、不回退 LLM。使用用户主动选择并授权上传的文件，不删除输入原件；需要转换时产物属于派生附件。采集音频保留策略、人声筛选与分段映射归 M1b/M2。Realtime/WebSocket 不作为本轮前置。
3. 提供 API key、base URI、协议类型、模型 ID、超时与适用参数设置；保留路径前缀，避免重复 `/v1`。拒绝带凭据 URL；分别测试文本、工具与转录能力；不支持模型列表时可手填，不把列模型成功当作能力通过。
4. 建立有 maxSteps/maxDuration/上下文及费用预算的 Agent 运行循环、会话/任务身份、不可变上下文、取消/重试/恢复和工具结果证据。流式 JSON 未完整或校验失败不得执行；取消、断网、限流、认证失败、重复/晚到事件不得造成重复业务写入。
5. 工具只来自启用模块和有效授权；资源/对象/修订与材料范围不能随焦点漂移。来源正文、模型输出、技能材料中的指令不能授予权限。至少用真实资源查询和一个已经实现且可撤销的业务修改证明端到端调用，不能注册未来空工具。

完成证据：本地受控 HTTP 服务覆盖两套文本协议、multipart、流式分片/工具、取消、重试、401/429、超时、断线、缺能力和恶意参数；对应 AT-09/10/11/12/13/44/49/50。实现与自动化不需要真实 API key，不能自动使用用户现有密钥或上传本地材料。

### P4：中文界面与完整基础工作流

1. 主内容区提供独立 Agent 页。会话历史、任务状态、材料/版本、授权范围、工具结果、停止/重试入口可见；与副驾驶共享同一会话/运行服务，切页不创建目标不同的任务。
2. 首次配置展示通道、各类目录与有效位置；在线配置可跳过，完成后均可在设置修改。未配置模型仍能使用已交付的资源、设置、检索和人工操作。
3. 资源总览覆盖已存在的资源、笔记、附件、备份和可再生缓存；未来模块显示未启用/尚无数据，不伪造数量或能力。数量、大小、位置、索引/托管状态、离线/缺失、筛选、打开、定位和修复来自同一服务。扫描异步可取消，不能阻塞主线程或泄露凭据。
4. UI 的读写经统一命令/查询。目录与凭据等必须用户交互的步骤明确展示，Agent 不能模拟授权；既有授权可复用。空、加载、错误、部分完成、离线、模块关闭状态有真实反馈。
5. 中文文案集中为稳定消息键，插值和日期/数字经本地化层。验证键盘、焦点恢复、窄窗、100/125/150% 缩放以及测试语言资源；具体视觉数值仍是可评审原型，不伪造 Q-08 已定稿。

完成证据：AT-49/50/51/55 与对应基础用例的真实 UI 流程、截图和恢复记录。原生输入法在最终 React 输入界面短测一次，合成 CompositionEvent 不可替代它。

### P5：最终验证与可审阅交付

1. 将实际存在的类型、领域/组件/集成、门禁反例、独立 Windows 包、恢复和参考机性能命令接入统一入口。先修定向失败，源码稳定后做一次最终匹配指纹的验收；旧实验目录继续保留。
2. 当前参考机、10,000 条资源元数据/50,000 检索块及原响应目标保持。重测新栈涉及的启动、可见交互、保存、上下文和搜索；记录样本量和原始值。显示器绘制与 DOM 状态、服务检索与完整 UI 检索分别说明。M1b 的 30 MiB EPUB 首屏不伪装成本轮通过。
3. 新证据用独立目录，报告必需用例/源指纹/失败传播。M0、M1a 进入验证、M1a 产品验收分别判断；尚有必需人工或技术定稿时不得标阶段通过。报告准确到 AT 的子场景，不将一个子场景提升为整条 AT。
4. 更新状态、支持矩阵、模块规格、仓库地图、质量门禁、决定与文档登记。公开文件不含个人绝对路径、设备标识、凭据或用户正文；敏感诊断只留独立本地位置。执行 `node scripts/verify.mjs` 和本轮新增真实门禁，自审并修复。
5. 交付：启动/打包说明、分支和 commit、未提交文件归属、最终源码指纹、独立包位置、修改摘要、逐项证据，以及一份集中待用户处理清单。将技术定稿、视觉选择、人工测试/配置、未获授权的 push/PR/合并等按事项写明推荐、证据、影响和批准后动作；不要重复索要已给授权。本地提交按 Git 节奏保存；远端操作、签名发布或真实用户数据迁移仅在对应已有授权内执行。
