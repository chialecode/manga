## 1. 交付原则

以可用的完整工作流作为阶段成果，同时把稳定引用、统一命令、模块生命周期和数据恢复作为基础质量要求。阶段按依赖推进，不在未知团队规模和验证结果前承诺固定日历工期。

文档完成仅意味着已经形成可评审方案。本文维护 POC 和 AT 的用例定义；实际执行结果统一见 [执行台账](status.md)，不能从本文的计划或预期判断功能已经可用。

0.2 新增[组合架构](../design/composable-ai-native-architecture.md)与[外部提供者](../design/external-providers-and-acquisition.md)验收。M2 元数据组合、M4 下载组合为新增建议排期，M0 先验证其可插拔边界；首批真实服务已选 Bangumi，下载协议已选 BitTorrent；具体引擎后续定稿。

POC-07 使用 MANGA 的统一契约和场景验证运行时候选。自研最小实现和适配实现均可纳入验证，最终选择以契约满足程度、可靠性和维护成本记录为准。

M1 明确按“Agent 主页面与连接/基础配置 → 阅读与人工记录 → 录音与整理”推进。M1a 用已存在的资源/配置查询及受控测试工具验证 Agent，不能注册未来模块的空工具冒充可用。M1 整体完成仍包含 M1b，不以聊天演示替代业务与恢复验收。

## 3. M0 验证任务

| 编号 | 验证问题 | 方法与必须留下的证据 |
| --- | --- | --- |
| POC-01 | 自研小说解析和定位是否稳定？ | 用 TXT/EPUB/MOBI/PDF、中文/日文/emoji 样本建立锚点，改变字号、窗口和解析规则，记录恢复结果；比较源结构、规范文本与 DOM 映射 |
| POC-02 | 用户语音能否正确采集并关联内容时间？ | 分别测试耳机和外放；记录设备、回声处理、录音采样偏移、延迟、暂停/倍速/跳转；报告误收录情况与定位误差 |
| POC-03 | 目标动漫样本和无转码导出可否实现？ | 建立 MP4/MKV、H.264/HEVC、AAC/ASS、多音轨和 VFR 矩阵，比较候选后端；验证关键帧切点、时间基、音画同步与不兼容拒绝；给出发布支持清单 |
| POC-04 | 能力协议是否支持停用与独立宿主？ | 用最小模块完成依赖解析、工具调用、事件、启停和晚到回调测试；在另一宿主装配小说核心能力 |
| POC-05 | 编辑和互嵌的基础行为是否可靠？ | 测试中文输入法、选区、撤销、块 ID、源编辑与布局编辑区分、循环嵌入占位；决定必要编辑/绘制基础技术 |
| POC-06 | 本地数据、搜索和恢复是否满足目标？ | 用基准库测试 SQLite 单写入、事务事件、全文中日文检索、备份往返、升级失败回滚和响应时间 |
| POC-07 | 组合运行时候选是否满足 MANGA 的契约、可靠性与维护目标？ | 同一 SDK、能力图、故障夹具和三个小型业务场景比较；验证多 Facet、single/many、依赖变化、显式关闭、重复释放、失败清理和恢复；记录版本、维护成本及限制，只选一个生产实现 |
| POC-08 | 多动漫数据库组合能否保留身份与用户意图？ | 两个固定假提供者产生冲突、同名跨媒介作品、超时与空字段；验证候选匹配、用户锁定、换源、断网和资料包往返 |
| POC-09 | 后装下载能否可靠连接本地导入？ | 用受控 HTTP 服务测试取消、ETag 变化、同名冲突、跨卷与磁盘不足；在文件发布/入库边界注入进程中断，证明恢复可核查且不重复入库 |

POC-04 增加模块停用提交屏障与旧 epoch 回调样本；POC-07 是 M1 组合机制的进入条件。POC-08/09 的早期原型只验证契约，分别在 M2 用 Bangumi、M4 用 BitTorrent 实际发行实现再次验收；HTTP/ETag 证据不证明 BT 分片和断点恢复。

POC 结果使用[验证报告模板](../templates/validation-report.md)，保存到 `docs/evidence/` 并链接到[执行台账](status.md)，包含可公开的平台/构建信息、样本指纹、依赖版本、步骤、实际结果、限制与设计决定。失败结果应回到模型或边界调整，不以绕过验收的特殊分支掩盖问题。

### 3.1 POC-07 运行时验证与选择

候选原型消费同一插件 SDK、静态清单和装配意图，运行同一组业务夹具；运行时差异留在宿主边界，不修改业务插件去迎合不同候选。原型分别运行，不要求同时装入一个生产宿主。

自研最小实现与适配实现都必须说明服务注册、作用域、清理、热变更和故障恢复的实际行为。先验证必要契约，再决定是否需要补充候选，不预设固定数量的完整实现。

| 验证项 | 共同验证输入 | 必须留下的证据 |
| --- | --- | --- |
| 依赖与配置 | required/optional、single/many、缺失/循环依赖、用户明确关闭、Bundle 冲突 | 确定性绑定、可解释影响链、无隐式重新启用；对应 AT-36 |
| 生命周期 | 中途激活失败、重复/重入释放、停止期间注册资源、晚到回调与提交竞态 | 启停时间线、残留资源计数、旧 epoch 拒绝；对应 AT-14、AT-37 |
| 结构变化与恢复 | 增删依赖、换提供者、候选失败、进程中断和配置重启 | 明确热变更/重建/重启范围；上次有效配置与业务数据可恢复；对应 AT-17、AT-48 |
| 多运行环境 | 服务与 UI Facet、解析 worker、IPC 取消、丢序后重新取快照 | 序列化协议、调用来源、断连恢复；M0 验证最小链路，M1 完成产品接入 |
| 三个组合场景 | 阅读器移除后恢复资料；双假数据库换源；下载组合加入后导入再移除 | 相同业务输出与数据身份；复用 POC-08/09 夹具，对应 AT-38、AT-41、AT-42/43 的原型子集 |
| 维护与成本 | 相同契约变化、依赖版本升级和故障诊断任务 | 实现/适配与测试投入、必要兼容层、代码依赖方向、平台限制、启动和启停资源测量 |

选择顺序如下：

1. 先检查必需契约和数据不变量。激活失败泄漏、停用后继续写入、身份变化或无法恢复，均不能以实现更快或代码更少抵消。
2. 通过必要行为后，比较维护范围、诊断能力、依赖演进成本和实测性能。分别记录运行时语义、契约补齐、兼容性和依赖升级的维护责任。
3. 记录选择理由、未选择候选的具体不足、热变更范围及仍需 M1/M4 完成的能力。只有满足必要契约且维护范围可控的候选可以进入生产实现。
4. 若所有候选都不满足，缩小或修正契约与原型后继续验证；不能默认为任一候选通过。结果选定后，发行版仅保留一个运行时实现，未选原型不进入生产依赖。

功能停用与重新启用属于 M1 必需行为。包代码升级、原生组件替换与复杂依赖图变化允许先要求重启，但必须准确展示实际生效状态。M0 的可信插件验证不证明第三方隔离已完成；AT-34/45/47 仍按 M4 实际执行边界验收。原型结果与完整产品验收分别记录，不能用场景子集通过替代 AT 用例完成。

## 4. 首轮测试样本

使用可合法使用、用户自有或自行生成的样本。这里定义样本性质，不将第三方内容放入仓库。

| 样本类别 | 至少覆盖 |
| --- | --- |
| 文本 | UTF-8/BOM、中文、日文、emoji、组合字符、重复句子、手动选择编码、较长章节 |
| EPUB | 多章节、插图、目录、基础样式、同句重复、正文结构变化、非法或超大容器条目 |
| MOBI/PDF | 未加密 MOBI、带文本层/扫描 PDF、图像页、版式与定位恢复；损坏/加密的明确失败 |
| 漫画 | PNG/JPEG 目录与 CBZ、EPUB/PDF/MOBI、非连续编号、同图重复、左右阅读、长图、旋转方向、超大尺寸 |
| 视频 | 基础 MP4 组合；必须覆盖 MKV/HEVC/ASS/多音轨；变帧率、非零流起始时间、不同关键帧间隔与不兼容拼接 |
| 音频 | 耳机、外放、静音、背景声音、设备切换、长停顿、角色专名、识别延迟和断网 |
| 内容关系 | 单对象引用、多对象互嵌、循环关系、已删除目标、跨项目材料、未知模块对象 |
| 文件系统 | 中文/空格/特殊字符路径、只读目录、移动文件、离线磁盘、相同文件名不同内容 |
| 运行故障 | 服务崩溃、重复消息、插件停用、晚到回调、错误模型输出、限流和预算耗尽 |

样本应有固定 ID 与内容指纹。媒体支持清单以具体样本组合和后端版本为单位，不能用一个扩展名测试结果覆盖全部编码组合。

## 5. 验收用例

所有用例都需要记录软件版本、依赖版本、输入和实际结果。表格为预期行为，执行前不得标记为通过。

### 5.1 M1 基础与完整工作流

| 用例 | 场景与操作 | 预期结果 |
| --- | --- | --- |
| AT-01 | 无模型配置打开应用，导入小说、创建人工笔记、切换模式并重启 | 基础流程可用；两个模式访问同一对象；布局、进度和已保存草稿恢复 |
| AT-02 | 导入含正常、重复、损坏文件的目录，中途取消；再移动其中一个文件 | 成功条目保留、重复处理明确、失败有原因；移动后按指纹修复，不能错连同名文件 |
| AT-03 | 阅读、跳转、重读、标记完成，再打开另一译本或改编作品 | 最后位置、已消费区间、完成状态分别正确；不同内容版本不混用进度 |
| AT-04 | 对中文、日文、emoji 和重复句建立选区锚点，改变排版并重启；替换源文 | 原版本内精确恢复；源版本变化后可靠匹配或明确待修复，不能误指另一处重复句 |
| AT-05 | 创建摘录、评论和结构化笔记，修改、撤销、查看修订并跳转来源 | 块身份稳定；原文、用户内容与 AI 派生内容可区分；保存与返回行为一致 |
| AT-06 | 选择麦克风录音，分别使用耳机/外放，测试设备拒绝与断开 | 真实状态与设备一致；不接入系统混音链路；报告外放误收录，不显示虚假录音成功 |
| AT-07 | 录音时翻页/切换资源，延迟返回 ASR；M2 追加暂停、倍速和跳转 | 笔记关联录音片段当时的资源和位置；不连续区间分别保存；未达到精度时可修正 |
| AT-08 | ASR 失败、整理失败、取消、重试；用户在重试前修改整理稿 | 原始录音/原文/锚点保留；重试不重复提交相同逻辑笔记，也不覆盖用户修订 |
| AT-09 | 使用界面和 Agent 执行同类创建命令，提交错误类型和越界参数 | 业务结果等价；输入运行时校验；无旁路数据库写入 |
| AT-10 | Agent 生成期间切换页面、修改目标、重复提交同一请求 | 目标不漂移；旧版本发生冲突，保留建议稿；幂等请求只产生一个逻辑结果 |
| AT-11 | 限制任务材料和已读范围，尝试越界检索；资料中加入伪装指令 | 所有查询/提取都受有效范围约束；来源内容不能扩大授权或触发额外副作用 |
| AT-12 | 为不同任务选择模型，测试缺失工具/音频能力、错误凭据、本地模型失败 | 能力检测与路由一致；错误可解释；不能擅自回退到未经授权的远程服务 |
| AT-13 | 运行长任务，隐藏侧栏、取消、限流、预算耗尽，再检查调用记录 | 状态准确、入口可发现、可停止；已有授权复用；用量估算与真实统计区分，敏感信息不进入日志 |
| AT-14 | 模块启停 50 次，制造硬依赖循环、缺失依赖、激活失败与晚到回调 | 无残留订阅/设备占用；状态可解释；旧工具与晚到结果不能继续写入 |
| AT-15 | 停用拥有内容的模块，导出、升级迁移失败，再重新启用 | 数据与预览保留；迁移失败可恢复；未知对象可完整导出；引用可重新解析 |
| AT-16 | 最小窗口、高 DPI、专注布局、纯键盘和中文输入法编辑 | 所有主要操作可达；面板可恢复；状态不只靠颜色；组合输入不被命令打断 |
| AT-17 | 在提交前后结束渲染/核心服务进程，重放事件与重复命令 | 已确认保存的数据恢复；未确认部分显示真实状态；重复事件不产生额外副作用 |
| AT-18 | 创建备份与资料包，导入空库或存在冲突的库，不附带部分媒体 | 内容/引用/指纹往返一致；冲突可选择；缺失媒体可定位；包中没有明文凭据 |
| AT-19 | 检索中文/日文标题、别名、正文和笔记，应用进度/范围过滤后重建索引 | 代表性查询可命中正确来源；过滤在内容出界前执行；缓存清理后可重建 |
| AT-20 | 在基准机器和库规模运行启动、首屏、检索与上下文测试，同时执行后台任务 | 记录 p95 和样本；达到 M0 定稿门槛；后台解析不阻塞交互 |
| AT-21 | 将小说与必要提供者放入最小独立宿主，导入主应用资料包 | 领域核心无 Electron/创作模块依赖；阅读、进度、书签和来源恢复可用 |

AT-07 的动态视频部分在 M2 验收。模型错误、重试和限流场景优先用可控适配器复现，再对选定真实提供者做有限契约测试；测试不依赖实时模型输出完全相同。

### 5.2 M2 媒介扩展

## 7. 质量检查的执行层次

1. **领域与契约检查**：锚点映射、引用闭包、进度区间、命令校验、幂等、修订冲突与模块生命周期。
2. **样本集成检查**：解析器、音频时钟、媒体后端、文件定位、数据库迁移与索引。
3. **端到端流程检查**：真实界面中的阅读→记录→引用→Agent，以及创作与导出。
4. **人工体验检查**：中文输入、阅读舒适度、对白误收录、文案依据、可访问性与错误恢复。
5. **打包与系统检查**：在目标系统的安装产物中复现关键流程。

测试应覆盖真实约束和失败边界，不以大量重复实现逻辑的测试替代样本与完整流程。通过后只有实现变化或新风险出现才扩大重复范围。

## 8. 发布门槛

- 当前阶段所有“必须”需求都有执行记录和可复现结果。
- ID、引用、已确认保存的记录和用户内容不存在已知的数据损坏问题。
- UI 与 Agent 命令没有绕过权限或业务校验的路径。
- 格式清单、模型能力和插件信任边界与实际实现一致。
- 备份与恢复至少完成一次往返验证；涉及格式升级时验证迁移失败恢复。
- 当前阶段新增页面提供上下文接口、键盘路径和关键错误处理。
- 已声明支持的操作系统通过打包验收；未验证的平台不作为已支持发布。
- 未完成的可选能力明确列出，不通过隐藏失败或改变验收含义宣布完成。
- 当前阶段的可选组合在安装/启用时必须满足其验收；未安装时不得成为本地流程的隐式依赖。配置状态、代码版本和数据迁移状态一致且可恢复。
