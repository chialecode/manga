## 1. 目标与当前判断

下一里程碑是 **M0 技术与契约验证**。本计划编写时仓库只有文档治理，没有应用源码、依赖清单、锁文件或安装包。**当前**自动化结果以 [执行状态](status.md) 与 [复核修复报告](../evidence/2026-09-19-m0-followup-review.md) 为准；不能把文档完成或原型成功写成产品验收通过，也不能跳过剩余人工项宣称可以开始 M1。

M0 要交付可重跑的验证工程、代表性样本、九项 POC 的实际证据、支持矩阵及选型决定，为正式产品开发消除关键不确定性。它可以有真实 Electron 窗口、持久化和端到端业务切片，但这些均服务于原型验证。

“一次交给 Cursor”在本计划中表示一次明确委派、按依赖连续实施、自测与修复，最后集中交付审查材料；不承诺单个上下文窗口就能完成，也不承诺实测一定成功。真实录音、输入法与人的产品决定仍须真实发生。人工检查前准备好可启动程序、固定步骤和结果记录，避免在开发中反复要求用户决定局部实现。

有两个必须区分的判断：

- **可开始 M0**：已授权的可逆原型、合成样本、契约与故障验证可以推进；现有技术待决项不阻止这些工作。
- **M0 可正式退出**：交付正本要求的关键实测、格式/性能/运行时定稿都已完成，人工检查及对应决定有证据。自动化通过但人工项未执行时，只能交付“可审查成果，M0 尚未退出”。

本计划不新增里程碑，不把九项 POC 拆成另一个较小的“已完成 M0”，M1a/M1b 的当前门槛由交付正本维护。

当前交付顺序已经确认：M1a Agent 主页面与基础配置优先，M1b 阅读/记录随后；准确阶段门槛见交付正本。下表作为交接摘要。

## 4. 人工决定、配置与参与

### 4.1 开始前的最小约定

将配套 prompt 作为下一任务提交，表示委派其中的本地 M0 原型工作；本计划文件本身不授予外部操作权限。默认执行方式如下，用户有不同偏好时在 prompt 前补充一次即可：

| 项目 | 建议执行约定 | 缺失时的处理 |
| --- | --- | --- |
| 已确认技术栈 | A-15 / [ADR-0007](../decisions/0007-technology-stack.md)已指定基础技术栈；对应 UI、编辑、存储驱动与工程基础按已选项实施和验证；其他未决项仍输出 proposed | 原型依赖和正式选型分别记录，不重问已授权库选择；组合内核等未决项不自动定稿 |
| 技术定稿权限 | 若希望 Cursor 同轮完成技术定稿，用户需明确委派“按证据定稿技术方案”的范围 | 未额外委派时，输出具体 ADR 推荐和证据，留一次集中决定；不能自行把全部 Q 标为已解决 |
| 本地依赖与工具 | 可安装项目依赖、下载原型所需依赖/工具至项目或缓存、生成合成样本、运行本地服务和测试 | 系统级安装、提权或组织网络限制若实际出现，列出具体缺项；先完成不受影响工作 |
| 数据范围 | 仅合成数据与独立临时数据目录；真实样本由用户明确指定后只读使用 | 不扫描个人媒体库，不把默认用户数据目录作为测试库 |
| 外部操作 | 默认仅本地实现和验证，使用本地假模型/假站点；交回 diff 和报告 | 推送、PR、合并、发布、真实计费调用或上传资料必须有本次任务的相应授权；已有明确授权继续有效 |

上述默认方式足以让开发连续推进，但完整 M0 退出仍取决于实测和决定。用户不需要在开始前挑选每个库，也不需要为了原型提前决定 M4 的提供者和第三方沙箱。

## 6. 各项实施细节与完成证据

### T00—T01：验证工程与共享基础

1. 读取 AGENTS、导航、状态、决定台账及专题正本，重新核对工作区与现有分支。已有任务分支继续；若位于 main，可按 Git 规则创建本地任务分支，保留已有改动。
2. 建立最小 TypeScript monorepo 验证工程，Electron 只负责验证窗口与平台边界。包管理、UI、存储和媒体依赖都注明“实验候选”，精确锁版本，记录许可、打包影响和替换成本。
3. 按实际需要建立包；候选实现可放拟议的 `experiments/m0/`，公共契约放 `packages/`，独立宿主按架构归属。目录目前不存在，创建后才更新仓库地图；不预生成完整产品目录树。
4. 公共 DTO/schema 覆盖稳定身份、资源版本、对象修订、命令、调用范围、取消、错误、模块清单和运行代次。复用现有语义，不另造平行协议；schema/包版本、修订与 epoch 分别表达。
5. 建立固定 seed/ID 的样本生成器和 manifest，包含预期结果、内容指纹、生成器/工具版本。时间等影响字节的输入固定；跨工具版本不能保证同一指纹时记录版本化产物，不伪称完全确定。
6. 提供合成 TXT/EPUB/图像/音视频、对象关系、假模型、两套元数据及本地 HTTP 服务。恶意压缩条目、错误输出、重复事件和崩溃点使用可控夹具。
7. 提供统一测试结果格式：用例/子场景、执行版本、环境、预期、实际、状态、证据路径。报告和原始结构化数据可以相互定位。

**完成证据**：从锁文件安装成功；类型、静态与依赖方向检查成功；一个真实反例能令相应门禁非零退出；样本可重建；所有数据落在隔离位置。安装成功不构成任何 POC 通过。

### T02：POC-01 文本与 EPUB 定位

- 自主实现领域定位语义；解压、文本解码、HTML 解析等基础能力允许使用经记录的依赖。
- 覆盖 UTF-8/BOM、手选编码、中日文、emoji/组合字符、重复句、长章节；EPUB 覆盖目录、插图、基础样式、多章节、结构改变、非法路径及超大条目拒绝。
- 按规范化文本 Unicode **码点**与左闭右开区间保存锚点；实际检验 DOM UTF-16 偏移与源结构的转换。不能用 JavaScript 字符串下标直接替代码点协议。
- 改字号/窗口、重启、变更解析规则、替换源版本，再核对位置。解析规则变化保留旧定位所需元数据；歧义重复句返回待修复，不能选第一处充当精确恢复。

**完成证据**：样本→锚点→原文片段的逐例对照、重排前后实际选区、版本/歧义结果及格式范围建议。关联 READ-01、NOTE-02、DATA-03 与 AT-04/18 的原型子场景。

### T03：POC-05 编辑与互嵌

- 用最小笔记块与引用卡片验证选区、撤销、块 ID、移动/复制、源编辑与布局编辑分离；只做足以判断编辑基础的画布/树夹具。
- 同一源笔记的两个引用实例应共享源内容，位置分别保存；循环、已删除目标和未知模块展示占位或预览。
- 检验真实中文输入法组合期间的 Enter、快捷键、焦点与异步更新，避免丢字或误提交。
- 在 Electron 中核对正常、错误、模块缺失、保存中/已保存状态；使用当前视觉方向和候选 Token，检查键盘、960×640 候选窗口、高 DPI/缩放。
- 优先验证一个有依据的 UI/编辑组合；出现硬缺陷或重要取舍时再补候选，避免只为排名构建多个完整 UI。

**完成证据**：自动化用例、最终窗口截图、人工输入法/键盘记录、依赖与替换成本、编辑基础推荐。关联 NOTE-03、CRE-02/04、UI-03；不将其写成完整 M3 或 AT-16/26/28 通过。

### T04：POC-06 存储、搜索与恢复

- 通过真实 SQLite 候选验证受控单写入；一次事务提交对象、锚点/引用、修订、操作与事务事件，提交后再通知。
- 让两个窗口共享 Profile；验证第二写入宿主的冲突处理、旧宿主异常退出后的恢复及并发配置修订。技术假设 A-13 以此取证。
- 以真实中日文查询检查标题、别名、正文和笔记命中；不能只凭“FTS 可用”宣布中日文搜索可用。检索/材料提取在结果出界前检查范围。
- 生成 10,000 条资源、50,000 文本块的基准库，记录查询集、索引构建与重建，验证已读/项目范围过滤。
- 测试一致快照与附件清单的备份往返、未知模块对象和必要位置映射保留、缺失媒体、冲突导入、失败迁移/只读恢复。关闭模块不能破坏备份导出。
- 在保存确认前后、事务提交与事件发布之间真实结束测试子进程，重启核对已提交状态、重放去重及未确认状态。
- 验证 Windows 本地打包产物的启动、SQLite 原生依赖、辅助程序定位与独立数据目录。开发模式成功不能替代打包冒烟；本地未签名原型包不等于正式安装/升级验收。

**完成证据**：数据库/附件逻辑对账、迁移故障与备份报告、搜索质量与耗时、打包启动记录、驱动及宿主/数据目录建议。关联 SEARCH-01、DATA-01—03、NFR-01/02 与 AT-15/17—20/35 的原型子场景。

### T05：POC-04 生命周期、网关和独立宿主

- 用同一小说核心能力在 Electron 验证宿主和无 Electron 领域依赖的独立宿主中运行；复用导入、定位、进度和资料包夹具。
- 实现依赖解析、工具/上下文注册、事件、启用/停用；验证消费者先停、共享依赖保留、激活失败清理、重复/重入释放、停止期间的新注册处理。
- 执行至少 50 次启停循环，统计订阅、定时器、线程/子进程、任务和设备句柄；记录收敛结果，而非只比内存某个瞬时值。
- 用可控暂停点制造“准入后停用、提交前换代、旧回调返回”的竞态，证明短事务提交屏障和模块/绑定 epoch 检查有效。无关目录变化不能取消全部任务。
- UI 调用和假 Agent 调用同一命令，验证 schema、可信来源、授权范围、幂等、版本冲突、固定目标、取消及恢复。原型不需要真实付费模型。
- 建立最小 service/UI/worker Facet 与窄 IPC 链路，验证非法消息、取消、断连和事件丢序后的快照重取；不能只在同一进程里调用函数来证明跨进程契约。

**完成证据**：两个宿主的同场景结果、调用/提交时间线、资源计数、真实进程恢复及越界拒绝样本。关联 BASE-01/03、AGENT-01/05、CTX-02/03、PLUG 与 AT-09—11/14/17/21/37 的原型子集。

### T06：POC-08 双假元数据提供者

- 两个固定提供者包含同名跨媒介、续季/特别篇、语言差异、字段冲突、空值、超时和限流。
- 验证 single、fallback、多源查询及字段选择；保留用户覆盖/锁定、显式清空与来源候选，评分不得无定义地混算。
- 换源前后比较 Work/Resource/Revision/Progress/Anchor 身份；歧义只产生待确认候选。
- 关闭全部提供者后断网、重启、编辑本地覆盖，再恢复提供者；确认本地资料不丢、用户修改不被覆盖。
- 导出/回导关联、候选、策略、来源与用户覆盖，验证另一宿主可核对身份。

**完成证据**：字段预期表、换源前后身份对照、断网/重启与包往返报告。关联 META-01—03、AT-39—41；只证明假提供者契约。

### T07：POC-09 下载、文件发布与导入恢复

- 用显式授权的 loopback HTTP 服务提供 Range/ETag、慢响应、断连、重定向和错误长度场景，服务只绑定测试需要的本地接口。
- 后装测试获取组合，通过同一标准导入命令完成文件入库；移除组合后文件、资源和记录仍可打开。
- 实现 Job、ArtifactRecord、ImportReceipt，分别记录传输、校验、发布和入库；相同逻辑任务恢复只产生一个入库结果。
- 在发布前、发布后记录前、入库事务前后注入真实子进程终止，重启核查文件指纹/回执，不能只抛异常模拟全部崩溃。
- 验证取消确认、ETag 变化时不拼接不同版本、同名不覆盖、下载完成但导入失败的独立重试、异常重定向、越界文件名和配额。
- 跨卷在目标卷暂存、核验后发布；使用真实不同卷验证，并记录原子不覆盖发布和刷盘的实际边界。进程结束实验不等于断电持久性证明。
- 磁盘不足优先在文件适配器注入明确写入失败；需系统验证时使用维护者准备的隔离有限容量卷，禁止填满工作盘。注入结果与真实文件系统结果分别报告。

**完成证据**：故障点×文件×数据库×回执矩阵，多次恢复/重复回调的最终身份一致，原有目标文件指纹未变。关联 ACQ-01—03、AT-42/43/46/47 的原型子场景；不代表真实站点或任意插件隔离通过。

### T08：POC-03 媒体与无转码导出

- 用有已知帧/声音标记的合法或生成媒体建立容器、视频/音频编码、位深、字幕、音轨、帧率、时间基、起始时间与关键帧间隔矩阵。
- 基础候选包含 MP4/H.264/AAC、外置 SRT/WebVTT；针对 MKV/HEVC/ASS/多音轨等期望样本明确实测或未测。纳入漫画目录/CBZ 的命名、方向、重复页和大图样本清单，不扩大为完整 M2 阅读器。
- 先验证 Electron 实际播放路径及受控探测/导出后端；浏览器路径不满足已需场景时，再验证必要的原生候选，比较部署与维护成本。
- 无转码实验记录请求切点、计划/实际切点、来源到输出时间映射；用解码和标记验证音画同步、非零起始时间、变帧率与不兼容拼接拒绝。
- 每项支持结论都绑定后端版本、构建参数和样本。现有 FFmpeg 是带 GPL/version3 配置的实验工具，其存在不构成应用再分发决定。

**完成证据**：机器可读矩阵、输出探测/解码结果、偏差与限制、后端推荐及后续分发问题。关联 READ-02/03、CLIP-02、AT-23/33 的验证子场景。

### T09：POC-02 真实采集与来源映射

- 将麦克风口述链路与媒体输入分离，真实设备状态决定录音成功/失败，保留主动开始/停止与错误入口。
- 保存采样偏移或真实采集时间戳、时钟域与校准关系；不使用 chunk 收到时间、上传结束或 ASR 返回时间定位。
- 静态文本翻页/换资源、媒体暂停/恢复/倍速/跳转分别形成位置事件；不连续区间必须分段，任务目标固定。
- 固定 ASR/整理响应验证延迟、超时、取消、重试与用户修订冲突；保留录音、转写、派生结果各自来源。
- 人工完成耳机与外放朗读、背景声音、长停顿、拒绝/断开/切换设备；报告采样偏移、开始/停止反馈、定位误差与外放误收录，记录最差值与分布。
- 若后续选择真实 ASR，再根据其范围做有限契约与质量验证；未提供服务不阻止采集/映射验证，报告不得声称 ASR 质量已定稿。

**完成证据**：自动时间映射用例、设备实测记录、片段与来源对照、误差/声学限制及 Q-05 建议。关联 VOICE-01—04、AT-06—08 的原型子场景。

### T10：POC-07 运行时比较与推荐

- 复用 T05 的 SDK、能力图、故障夹具及 T06/T07 场景；候选分别运行，业务模块不导入具体运行时类型。
- 先实现或适配一个有依据的最小候选。记录其他候选的筛选依据；只有现有证据不足以判断或候选存在缺口时，补充必要的可执行候选，不预设必须开发两套完整内核。
- 同样验证 required/optional、single/many、Bundle 冲突、用户明确关闭、版本不兼容、确定性绑定与清晰依赖诊断。
- 重跑激活失败、50 次启停、重入清理、晚到回调、提交竞态、候选准备失败、结构变化、配置重启和上次有效配置恢复。
- 三个共同场景为阅读器停用/恢复资料、双假源换源、后装下载→导入→移除。可以用微型阅读夹具证明数据边界，不能将其写成完整漫画功能。
- 记录同一契约变化、依赖升级和故障诊断任务的实现/适配/测试工作、兼容层、资源与平台限制；不编造长期维护工时。
- 先按硬性不变量淘汰泄漏、停用后写入、身份变化和不可恢复的候选，再比较维护与实测性能。全部不满足就报告未选定，继续已授权修复，不能改弱契约制造胜出。
- 明确热停用/重启生效范围，最终生产设计只保留一个运行时；落选实验与生产依赖隔离。组合内核与 Agent 推理运行时不是同一选型问题。

**完成证据**：共同输入与输出、硬门槛逐项结果、维护任务记录、推荐及淘汰理由、ADR。关联 PLUG-05/06、NFR-05、AT-36—38/48 的原型子集。

## 7. 性能测量与验证入口

性能目标的唯一正本是 [需求第 6.2 节](../product/requirements.md#62-初始性能目标)。计划不另建一张目标数值表，避免两份标准漂移。

测量前固定设备、依赖版本、构建模式、数据规模、查询集、冷/热定义与重复次数，保存每次原始数据。建议常规查询/反馈收集至少 100 次有效观测、进程启动/首屏至少 30 次；样本不足时说明局限，不能只报最好的一次或把平均值叫 p95。操作系统文件缓存未清空时，进程重启不能宣称磁盘冷缓存测试。

分别记录索引构建、重解析、已索引首屏、本地查询、任务反馈与远程延迟；后台工作并行时也核对交互。M0 中的原型结果用于定稿门槛，完整产品的 AT-20 要在 M1 重新执行。参考环境按已确认的 A-14 使用当前 Windows 11 电脑，保留目标值；测量范围及不足必须单独注明。

治理+类型入口仍是 `node scripts/verify.mjs`。M0 命令已实现并写入 [仓库地图](../dev-rules/repo-map.md)；下表是交付时的实际状态，不再是拟议接口。

## 8. 报告、选型与审查交付

每项 POC 使用 [验证报告模板](../templates/validation-report.md)，建议输出 `docs/evidence/YYYY-MM-DD-poc-01.md` 至对应的九份报告，以及一份 M0 汇总。报告分开自动、模拟、真实设备和真实文件系统证据，子场景缺失时不把父项写为全部 passed。重新运行使用新版本证据，保留历史失败。

交付材料至少包含：

1. 可运行的验证工程、锁文件、固定样本生成器和明确的安装/执行步骤。
2. POC-01—09 的报告与机器可读结果；每项附 commit、未提交 diff/内容指纹、环境、样本指纹、精确命令、预期/实际与限制。
3. 文本/EPUB/图像/视频/字幕支持矩阵；性能原始数据与基准环境；人工设备/输入法/跨卷结果或明确的未执行清单。
4. UI/编辑、存储/宿主/目录、组合运行时、媒体与性能的技术建议或已获有效决定的 ADR。相关范围可以合并为少量有清晰主题的 ADR，无需每个小工具一份。
5. 实际模块规格、契约说明和独立宿主演示；公共契约改动同步领域、Agent、组合及外部扩展正本。
6. 更新 `status.md`、仓库地图、质量门禁、决定台账、文档登记和相关导航。原 POC/AT 编号与语义不弱化，未执行的产品 AT 保持 not-run。
7. 集中人工检查单：每项入口、设备/样本、步骤、预期、记录位置、失败后的复现方式；不要求用户自己读源码推测怎样测。
8. 最终审查摘要：基线与当前版本、差异列表、已通过/失败/阻塞/未执行、决定来源、已知限制、M0 是否达到退出条件、M1 是否允许开始及具体原因。

正式选型前查决定台账。即使设计表中写有“SQLite 单写入采用”等取向，也不能覆盖 A-04/A-13 的实测与定稿状态。若用户没有委派最终技术决定，ADR 以 proposed 交付；若有明确委派，技术负责人可在证据充分时定稿，并记录该依据。产品偏好、公开分发与新增数据操作不能由技术委派推导。

### 8.1 M0 退出判定

- 九项 POC 均有与当前实现版本匹配的结果；必要场景完整，失败已修复或通过有明确依据的范围决定收敛。
- 定位、提交屏障、身份稳定、备份恢复、获取幂等这些不变量通过真实可复现验证；不能以维护成本或演示成功抵消失败。
- 麦克风/耳机/外放、真实输入法、目标平台打包与实际跨卷等本计划承诺的实机项目有证据；缺项保持未完成。
- 格式、性能、运行时及 M0 截止的技术边界已经依据结果定稿，未决范围有明确归属和下一阶段截止点。
- 全部适用检查通过；没有未解决 P0/P1，也没有与当前必需项冲突的延期 P2。
- 最终报告只判定 M0；任何 M1—M4 产品验收需要对应阶段真实执行。

若人工项或关键决定尚缺，交付代码、已执行证据和具体补测入口，结论写“自动化工作已交付，M0 未达到退出条件”。这是如实报告剩余工作，不能把 blocked 当通过，也不能因局部阻塞停止其他可完成的工作。

### 8.2 交回审查时的优先核对项

审查者先复现完整命令，再抽查 Unicode/重复句锚点、停用与提交竞态、真实崩溃恢复、文件发布/入库边界、未知对象包往返、换源身份、IPC 调用来源和真实输入法证据。重点检查是否存在“只 mock 核心存储”“catch 后吞失败”“跳过的测试仍报成功”“按 UI 当前焦点提交旧结果”等实现问题。

用户交回时提供分支或本地改动、M0 汇总报告路径及人工结果即可；无需手工复制全部日志。若有经授权创建的 PR，附其链接，避免审查者猜测被测版本。
