1. 工作流与状态以需求/交互正本为准；Figma 帧标注对应流程、状态、视口和组件 variant，给出操作结果，而非只有一张静态图。

### 14.3 插件可替换与真实停用的最小落地

先在现有代码中抽最小格式/渲染适配边界，参考模块职责正本；不为 MVP 先建设任意第三方插件市场。以下是待实施合同，应通过公共 DTO 与模块规格落地，不是现有 SDK 类型声明：

1. 格式能力负责打开、目录/页/文本抽取、位置解析与资源读取；阅读/播放 UI 消费能力。资源库持有永久身份、进度和记录，第三方对象留在适配层。
2. 记录引擎及规范化表示版本；同一原件换引擎不静默创建/搬迁资源修订。旧锚点映射必须可验证，映射失败显示待修复并保留原文/历史，不重建用户数据库。
3. 启停接入现有 kernel：停止任务/worker/解码、释放订阅和 object URL、关闭音视频/预加载、拒绝旧 epoch 结果；仅隐藏页签不算停用。共享依赖仍被其他模块使用时保留，资源/笔记/引用仍可管理和导出。
4. 用合成 Profile 验证“开书/播放→创建引用→停用→查看旧笔记→重新启用→返回来源”以及停用过程中的晚到结果。原生引擎升级允许明确要求重启，不承诺所有二进制任意热替换。
5. 候选验证记录版本/许可、失败矩阵、包体/离线资产和同规模窗口指标。能安全隔离的候选先做可逆原型，最后把有证据的推荐交 Q-14，不在每次适配时要求用户选库。

### 14.6 PDF.js 替换与一次性交付的 MVP 边界（2026-09-25）

**决定依据与状态。** 用户在 A 复核 8.21 期间要求先移除自编 PDF 解析器、考虑开源方案，以 MVP 和迭代替代持续返工，并明确选择“A 定方案并更新唯一计划，给 B 一次性实施任务”。B 8.23 已按本节接入 PDF.js 6.3.289 legacy，证据在 `docs/evidence/m1b-reading-notes/b10-pdfjs-mvp`；A 8.24 已复核，F-09 本批组合关闭、F-07.1—3 未收敛。B 8.25 已按该差异返工并完成自检，证据在 `docs/evidence/m1b-reading-notes/b11-pdfjs-text`；A 8.26 已独立复核，并直接修复晚到 TextLayer 与在途取消两处生命周期缺口，最终技术审查收敛；证据在 `docs/evidence/m1b-reading-notes/a-b11-review`。用户 ACT-01 反馈的两项问题由 A 8.27 修复，见本节末段。不是产品验收。官方资料刷新日期 2026-09-25：[PDF.js 分层](https://mozilla.github.io/pdf.js/getting_started/)、[Display 示例](https://mozilla.github.io/pdf.js/examples/)、[API](https://mozilla.github.io/pdf.js/api/draft/api.js.html)、[v6.3.289 发行](https://github.com/mozilla/pdf.js/releases/tag/v6.3.289)。GitHub 显示未归档、2026-09-25 有更新，稳定版发布于 2026-08-29；npm 当前稳定版与本地原型同为 6.3.289，Apache-2.0，Node 要求 `>=22.13.0 || >=24`。此前 14.5 的实际修复/维护样本仍有效。本轮[结构化查证](../evidence/m1b-reading-notes/a-b9-rework-review/pdfjs-mvp-assessment.json)与 [Display 探测](../evidence/m1b-reading-notes/a-b9-rework-review/pdfjs-display-probe.json)分别记录来源和运行范围。

**采用 PDF.js 的 Display API + TextLayer。** PDF.js 处理 PDF 对象、字体、图像和绘制；MANGA 处理原件访问、资源/修订/页身份、规范文本映射、进度、笔记、权限和生命周期。已有 React 壳无需嵌入整套 viewer。React-PDF 官方组件也包装 PDF.js，但不能免除 MANGA 的位置映射和生命周期整合，本批不增加第二层查看器依赖；MuPDF 的 AGPL/商业分发路径增加当前不必要的许可决定，故不选本批路线。A 用已安装 PDF.js、离线标准字体和 Node Canvas 对不等宽、Tc/Tw、50 Tz 三份输入实际绘制，合写/拆写两行对应区域像素相等（3/3）。这证明该路线能处理当前反例；Electron 集成、TextLayer 选区、处理中取消和旧锚点仍由下列门禁验证。候选 `accepted=false` 保持到实际集成交付，不能继续只交 devDependency 原型。

**B 按一次完整变更实施以下内容：**

1. 在既有 reader-engine 边界接入 PDF.js；新增必要的异步 PDF 分发，使 `product-app.ts#parseIncoming`、`repairSource`、`parse-worker.ts` 都经同一适配器，信号/代次屏障继续有效。精确锁定本轮已核对版本；安装时核实有无维护变化，避免把无关全栈升级捆绑进来。原有非 PDF 分发和领域 DTO 保留。
2. 产品 PDF 页面使用 PDF.js `page.render` 的 Canvas 与官方 TextLayer。原件只通过宿主按资源/修订授权提供，renderer 不接受任意磁盘路径；渲染原件通道限定本地用户阅读，不自动给 Agent 全书 bytes 或绕过已读范围。新 bytes 导入的 PDF 必须有持久、可导出/恢复的原件：无来源路径时保留其合成/用户提交的 bytes；外部索引文件仍按原契约保护，文件变更/丢失不得静默显示另一修订。扫描页正常显示、明确无可选文本，不生成 OCR。保留翻页、适配宽度/缩放、选区摘录、来源返回及重启恢复；不在本批增加 PDF 编辑器。
3. 从产品源码和包移除 `pdf-text.ts` 的 PDF 字体/操作符解释器，以及 `formats.ts` 的自研 PDF 解析路径和 PDF 专属 SVG 文本绘制。共用 `PageRender` 类型与 EPUB fixed-layout 的现有绘制若仍使用，抽为中性类型/组件；不能误删 EPUB/MOBI 的可用行为。旧存储模型只作为被动兼容数据读取，不作为第二套活动 PDF 引擎；原件不可用时明确显示已存文本/来源修复入口。不要为了历史测试保留自研 PDF 运行时，也不要在 PDF.js 出错时静默调用旧解释器。
4. 新 PDF 记录引擎/表示版本，沿用 `page-N` 身份。PDF.js TextItem/TextLayer 到 NFC/LF/code-point 的映射由一处适配逻辑建立；空格、EOL、代理对和规范化合并不得用字符串长度猜定位。旧修订/locator 不自动改写，不把换引擎当新原件：保留已存规范文本作为旧来源依据，绘制文本层与旧表示的引用匹配可唯一确定才高亮；歧义用 `needs_review`，缺原件保留旧引文/历史并提供修复入口。只在合成旧 Profile 上测试，真实迁移 not-run。
5. 离线随包提供版本匹配的 worker、CMap、标准字体及所用 WASM 等资产和许可，开发启动与 Forge 包各验证一次，不使用 CDN。复用现有受控本地资源/IPC 与 CSP；PDF 中脚本/外部资源不作为普通阅读自动执行或访问。异步 render/text/load 任务绑定会话与代次，换书/关页/停用时 cancel/destroy 并释放 worker、Canvas 缓存、订阅、object URL；只保留当前/有界邻页，不能预渲染整本书。现有主进程/解析 worker 是 CJS 构建，PDF.js 为 ESM，B 必须实际验证打包加载方式，不把 Node 原型的动态 import 成功当 Electron 包成功。
6. 同批修复 F-09：在全部 ID/属主规划前收集显式 skip 的幸存边；以最终状态核对 ref、块载荷、历史、锚点、修订属主与索引。`object replace + ref skip + anchor duplicate` 等无法同时满足的组合可以明确拒绝，无需为 MVP 支持所有冲突组合。拒绝时权威表和附件不变，保留恢复日志允许记录失败；不得先删后派生、不得只查同块有任意 ref 就宣布来源一致。
