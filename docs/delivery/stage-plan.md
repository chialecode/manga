## 4. 数据与契约

所有新表与字段经迁移加入：迁移前自动备份，失败时回滚，不改变已有 Work、Resource、Anchor、Progress 的身份与含义（DATA-01—04）。资料包与项目包都包含新数据，并做往返测试。

### 4.1 项目（CRE-01）

- `projects`：名称、目标、状态、创建与更新时间。
- `project_materials`：只记录引用（作品、资源、锚点、笔记、录音、摘录、白板、导图、文稿），不复制个人数据，删除项目不删除被引用对象（AT-25 的“所有权与材料关系分离”）。
- `project_terms`：项目术语表，与语音词典分开，可以一键导入作品词典。
- 工作模式的会话绑定项目（`sessions.project_id`）：会话的材料范围、模型覆盖与授权遵守项目范围，切换项目不扩大授权。

### 4.2 白板（CRE-02）

- 白板文档保存节点、连线、分组与视口。节点分三种：自由文本、卡片、引用实例。
- 引用实例只保存目标对象 ID、局部定位与自身布局。源内容在源对象里编辑，多个实例同时更新；移动一个实例不影响其他实例。
- 撤销与重做使用操作日志，不靠整板快照；重启后恢复布局。

### 4.3 思维导图（CRE-03）

- 单根树：节点 ID 稳定，记录父节点与排序键（分数索引）。
- 移动节点前检查目标不是自己的后代，否则拒绝。折叠状态单独保存。
- 引用是挂在节点上的附件，不参与父子结构。
- 导出 PNG、SVG、Markdown 大纲与 OPML。

### 4.4 互嵌（CRE-04）

- 统一的 `embeds` 关系：源对象、目标对象、局部定位、模式与状态。
  - 模式分实时和快照。快照模式保存当时的内容快照与版本。
  - 状态分为有效、目标已删除、模块已停用、无权限、循环。
- 渲染时检测循环并截断，显示“循环引用”。目标失效时保留可读的摘要和恢复入口。
- 模块停用时显示占位，数据保留。
- 笔记（Tiptap 节点视图）、白板节点、导图节点三者都能嵌入其余两种对象的整体或局部（AT-28）。

### 4.5 文案（CRE-05）

- 文稿是 Tiptap 文档，带版本历史。
- 生成操作包括提纲、续写、润色、翻译、按术语表改写、引用材料生成。结果作为“建议”保存，附引用的材料与版本；先显示差异，用户采纳后才写入文稿，可以撤销。
- 源材料更新后，旧建议标出“依据已变化”，提供新旧对比，由用户决定保留或重做（AT-29）。生成内容不冒充原文：引用内容和生成内容在界面上要能分开。

### 4.6 资料搜寻（CRE-06）

- 本地搜寻复用全文检索：作品、笔记、录音转写、摘录。
- 外部只做用户给定网址的摘录：抓取 → 正文提取 → 用户选取片段 → 保存。摘录记录 URL、获取时间、内容哈希、正文、选取的片段与本地版本。再次更新网页时生成新版本，不覆盖旧摘录。
- 不内置网页搜索引擎（需要另配 API 密钥），以后按需求再定。

### 4.7 语义检索（SEARCH-02，可选）

- 默认关闭，在设置中启用并选择 Embedding 连接。
- `index_versions` 保存模型、维度、分段方式与版本号，每个版本单独一张向量表。切换模型或维度会建新版本，在后台重建；重建期间旧版本与全文检索照常可用，切换完成前不混用。
- 检索结果带定位引用，检索范围先受权限与进度约束（例如防剧透开启时不超过已读位置）。

### 4.8 项目包

- 项目包是 zip，内含清单（格式版本、项目 ID、对象列表与哈希）、对象数据以及被引用的个人材料快照。
- 导入时校验哈希与版本。ID 冲突时按“导入为副本”处理，引用随之重映射。
- 往返后，引用、互嵌与来源仍然可以解析，或者明确显示失效状态。

### 4.9 字幕的默认排版（A-59，Q-22）

**取自标准的部分。** GY/T 288—2014 的第 4、6、8 章与 GY/T 357—2024 的第 9 章给出的相对数值一致：

| 项目 | 默认值 |
| --- | --- |
| 对白字幕区 | 位于画面底部；宽为有效画面的 90%，水平居中；下沿距画面底边 5%；高为画面高的 10% |
| 字高 | 画面高的 5%，容差 ±1% |
| 字体与颜色 | 黑体、楷体、宋体一类的简体中文字体；白色（容差 90%—100%） |
| 排版 | 居中；同一画面字体、字号、颜色统一；不用斜体（唱词除外）；两人同时对话用上下两行 |
| 说明性字幕（地名、时间、人物等） | 放在片头片尾字幕区，即画面中央宽、高各 80% 的范围（GY/T 357；GY/T 288 为 90%） |
| 宽银幕放在画面下方 | 画面比例为 2.35:1 或 2.39:1、且下方黑边够高时，对白区可以放到画面下方：上沿与画面下沿重合，宽 90%，高为画面高的 10%（GY/T 288 第 4.2 节） |

**Agent 默认（标准没有规定，用户可在 Q-22 修改）：**

| 项目 | 默认值 |
| --- | --- |
| 可读性 | 白字加约字高 6% 的深色描边和轻微阴影，不加底框 |
| 字体 | 默认用系统的黑体类字体：微软雅黑，退回黑体，再退回思源黑体 |
| 双语单条字幕 | 含中文的行在上，按标准字高；其他语言的行在下，字高为中文行的 75% |
| 主字幕加次字幕 | 次字幕在主字幕下方，字高为主字幕的 75%；两者合计超出对白区时，以底边为基准向上扩展 |
| 带 `{\an8}` 等上方位置标记的字幕 | 视为说明性字幕，放在上方字幕区顶部居中，字高为画面高的 3.7%（相当于 4K 下 80 像素） |
| 宽银幕放在画面下方 | 默认自动：黑边高度不小于画面高的 10% 时放在画面下方，否则放在画面内 |

**适用范围。** 以上默认只用于没有自带样式的文本字幕：SRT、WebVTT、MKV 内嵌文本字幕。ASS 默认保留自带样式。

**MANGA 自己生成字幕文件时。** 以后导出带字幕的内容时，两句字幕之间至少间隔 80 ms（GY/T 357 第 9.3.2 节）。本阶段的粗剪不导出字幕，这条先记在视频模块规格里。

### 4.10 语音转录词典（A-66，VOICE-09）

**数据。** `dictionary_terms` 记录以下字段：

- 范围：全局或作品；
- 作品 ID；
- 词条、“听成”的写法；
- 来源：手写，或 `metadata:<提供者>:<类别>:<外部 ID>`；
- 创建与更新时间。

迁移时把已有的 `work_terms` 并入，作为手写词条，同时保留旧命令的兼容层。

**从资料加入。** 从已缓存的角色与人员数据加入词条，不额外联网：

- 角色：中文名与原名；
- 声优：中文名与原名；
- 专有名词：作品名与别名。

自动词条与手写词条去重，手写优先。刷新资料时只增删自动词条。

**转写提示。** 拼接顺序是：作品手写词条 → 作品自动词条 → 全局词条。提示上限按转录模型配置（默认 600 字符，可在设置页调整），超出时截取并在设置页提示被截掉的数量。

**整理与润色。** 把作品词典与项目术语表作为术语表提供给模型。

**提示回显检测。** 转写结果主要由词典条目按提示中的顺序连续组成，或者同一词条反复出现时，判为提示回显：该段标为失败，可以重试，不写入正文。

### 4.11 其他契约

- **模式。** 只改显示名与入口位置，内部值和已保存的布局不变。
- **对话。** 娱乐模式在 Profile 设置里记录当前全局对话；历史就是该模式下的其他共享对话，只读列出，可以继续。
- **粗剪。** 序列由片段组成，每个片段记录源资源与修订、请求的入点和出点、顺序。导出任务记录计划切点、实际切点、兼容性检查结果、临时文件与完成文件。
- **插件包。** zip 内含：
  - 清单：ID、版本、发布者、所需宿主版本、声明的权限、入口；
  - 载荷；
  - 签名：对清单与载荷哈希的 Ed25519 签名。

  安装到 Profile 的插件目录，按版本保留上一版本以便回退。信任库包括内置的第一方公钥和用户显式信任的公钥。未签名、签名不符或执行型而未被信任的包，一律拒绝（AT-34）。
- **获取。** 下载计划包含：
  - 来源：磁力链接或种子文件；
  - 选中的文件；
  - 目标目录授权；
  - 预算：大小上限、带宽、是否做种。

  任务状态包括排队、获取元数据、下载、校验、发布、入库、完成、暂停、失败、取消。发布与入库都有回执，可以单独重试（AT-43）。引擎的恢复数据放在 Profile 的获取目录里，换引擎时不复用不兼容的断点（AT-46）。

## 6. 界面要点

- **标题栏。** 从左到右：侧栏按钮、模式分段控件（两个图标）、标题。窄窗时分段控件保持可见，标题可以截断。图标按钮至少 28 × 28 px，焦点可见。
- **阅读器。** 正文为主。顶栏放返回、标题、目录、搜索、书签、设置、全屏，底栏放进度；不操作约 2 秒后收起，鼠标移到顶边或底边、或按键时出现。阅读设置是右侧面板，即改即生效。小说的翻页与滚动模式沿用已有能力。
- **对话页（娱乐模式）。** 顶部右侧放“开启新对话”和“历史”。历史是一个列表面板，显示标题、时间与首条消息摘要，点开可以回看并继续。左栏不变。
- **设置。**
  - 新增“语音转录”和“插件”两页；
  - “播放”里加字幕样式；
  - “资源库”旁边加“下载”，在获取插件安装后出现。
- **工作模式。** 左栏下部是项目会话。项目页有“材料、白板、导图、文稿、摘录”几个页签。白板与导图占满主面板，右栏 Agent 照常可用。
- **粗剪。** 从动漫播放器的“…”加入序列。序列页显示片段列表、预览、请求区间与实际区间对比，以及导出按钮与进度。
- **视觉。** 沿用白灰粉主题（Q-08 仍待用户评审）。新页面在宽窗、窄窗、矮窗与系统 125%、150% 缩放下截图自检。

### 16.5 数据迁移（schema v11）

v10 还没有发布，但用户试用打包版时，本机的 Profile 已经升到 v10，所以不能改 v10 的定义，要新加 v11。沿用现有做法：迁移前备份，失败回滚，可以中断后重复执行。本轮所有表的改动合成这一次迁移。

| 内容 | 变更 |
| --- | --- |
| 资源 | 删除条目后，资源的作品为空。新增“离开作品的时间”，扫描与导入看到它时不重新分组 |
| 用户内容文件夹 | `work_folders` 的归属增加“资源”；`work_files.work_id` 可以为空（SQLite 要重建表）；新增文件类型“笔记” |
| 截图 | `screenshots.work_id` 可以为空（重建表） |
| 删除条目后留下的作品级内容 | 保存删除前的标题。B 选改动最小的做法，写进数据设计 |
| 文件重排 | 不在 schema 迁移的事务里移动文件。迁移只改表；按新规则重排文件、补写笔记文件，是启动后的后台任务，沿用 `file_moves` 日志，可中断后重做 |

迁移用例：

- v10 资料（含关联与没关联的作品、截图、录音、笔记）升级后内容一致，文件按新规则就位；
- v9 → v10 → v11 连续升级；
- 中途中断后重做，包括文件重排做到一半；
- 失败时回滚到 v10；
- 备份与恢复往返。

只用合成资料。真实 Profile 迁移仍受 ACT-05 第（2）项约束。
