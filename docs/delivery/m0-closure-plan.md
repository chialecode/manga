## 1. 范围和停止线

在现有验证工程上补齐 M0 的关键不确定性，修复用户发现的回放问题。原 [执行计划](m0-execution-plan.md) 保留完整背景；本页管理复核后的剩余工作，不重新建仓、重做脚手架或把已通过用例当未开始。

M0 的通过可以是“测得可行并给出约束”，也可以是“证实某候选不支持，给出有证据的替代/拒绝方案并完成范围决定”。测试失败必须被解释和处置，不能简单删除用例或把未实现写成“不支持”。格式承诺或阶段范围的变更须有有效决定。

只实现可验证的最小竖向原型：选区定位、少量块/嵌入、媒体/采集时间线、UI/service/worker 链路、假提供者资料包。这里的“阅读 DOM 联测”不要求完整阅读器产品，“工具范围”不要求完整模型 Agent，“多 Facet”不要求第三方插件商店/安全沙箱。完整资源库交互、白板/导图、ASR 服务、真实站点、完整粗剪 UI、安装升级和签名发布按 M1—M4 原阶段执行。

所有工作默认本地执行、使用合成样本与独立临时 Profile。现有真实笔记/录音不用于破坏性测试、不自动删除或上传。旧录音/数据库兼容性先用旧版合成夹具验证。

### R0：核对现状，不重做已有工程

1. 执行 `git status --short --branch`，阅读入口正本与实际代码；记录起始版本、未提交内容及 `sourceFingerprint`。
2. 先执行现有 `node scripts/verify.mjs`，将现有失败修复或准确登记环境原因。
3. 按交付正本逐项建立“必需场景→测试入口→实际证据→当前状态”的覆盖表。代码存在、函数级断言、界面链路和物理设备证据分别说明。
4. 现有 `MinimalActivator` 是故意缺少清理的反例，不是可公平胜出的候选。原报告中“自动化全部完成”不作为事实前提。

### R1：先解决用户可见的回放缺陷

代码入口：`experiments/m0-desktop/src/renderer/renderer.js`、桌面 preload/main、`experiments/m0/src/application/app.ts` 中的录音保存和读取。诊断见 [实机反馈](../evidence/2026-09-19-m0-device-followup.md)。

必须完成：

1. 用当前 MediaRecorder 自动生成合成录音，重现首次加载 `duration = Infinity`，建立真正穿过保存→重启→读取→播放器的回归。不能只注入一个正确 duration 数字来让断言通过。
2. 选择受控的容器完成/索引、封装或播放器加载方案，使总时长、结束位置与实际可拖动播放一致。保留原音频；已有缺时长 WebM 提供兼容读取或可恢复的派生文件。不得覆盖原始录音或拿墙钟时长伪装可寻址能力。
3. 保留正在播放的元素/状态；普通笔记自动保存、刷新资源和切换侧栏不得移除播放器。重复打开同一录音不重复分配播放器，替换/关闭时释放 Blob URL；处理乱序读取结果。
4. 增加稳定、可见、键盘可达的“导出录音”操作，不依赖原生三点菜单。特权进程校验附件归属并管理保存对话框；renderer 不获得任意路径读写。取消不报成功；目标冲突、无权限/磁盘错误有真实反馈。原格式导出先保证字节一致；若派生格式，明确格式且验证可播放与内容时长。
5. 保存失败重试复用同一次录音的稳定幂等身份；验证“已持久化但响应丢失后重试”不产生重复录音。保留现有未关联附件限制的准确描述，不以清理为由删除用户数据。

最小验证矩阵：1 秒/较长录音；立即首次回放、重启后回放；首次播放前拖动和结束后重播；回放中笔记自动保存；连点打开两条录音；导出成功/取消/错误；100%/125%/150% 与窄窗；无时长旧 WebM。用实际媒体状态和导出文件验证，不以按钮可见代替功能成功。

### R2：真实 DOM、源定位与最小块交互

复用 `experiments/m0/src/domain/` 中既有文本、EPUB、定位和编辑模型，不创建另一套 ID/偏移协议。

1. 在 Electron 中渲染 TXT 与 EPUB 的代表性正文。用 DOM Range 选取中日文、emoji、组合字符和重复句，保存真实 locator，再从笔记跳回并校验高亮内容。包括较长章节，不以固定 32,000 字符预览覆盖完整定位范围。
2. 改字号/窗口后恢复同一来源；源版本、解析规则或结构变化后按协议精确恢复或明确待修复，禁止默默跳到另一处同句。验证 Unicode 码点与 DOM UTF-16 映射边界。
3. 少量真实可操作块验证稳定 blockId、分拆/合并、选区、撤销/重做；源编辑与布局移动分别改变应改变的数据。最小嵌入卡验证互引、循环、删除目标、未知对象占位；无需白板/导图成品。
4. 保留原生输入法守卫与保存恢复。若候选编辑器发生更换，先自动回归再给一次针对性原生 IME 检查，不能继承旧 textarea 的人工结论。
5. 为编辑基础提出一个有证据的推荐，说明自研范围、替换成本和维护负担；不强制为比较搭建两套完整 UI。

验收：真实 UI 选区→命令→SQLite→重启→来源高亮的链路可重跑；选区/历史与块身份断言通过；保留界面截图和失败边界。完整阅读器体验和全部 AT-04/18 仍属后续产品验收。

### R3：采集时钟与内容位置联合测量

1. 接通实际采集样本计数/音频时钟、renderer 单调时钟与来源事件；记录采样率、起止、设备设置、丢失或暂停区间。MediaRecorder 的 `start` 或 JS 调度时间不能冒充硬件采样时刻。
2. 由真实播放器事件驱动播放/暂停/倍速/跳转分段；文本翻页/换资源保留正确版本。用合成音频中的固定标记与固定 ASR 夹具，测量每段应关联的来源和误差，覆盖识别延迟/失败/取消/重试及回调到达时焦点已变更。
3. 验证暂停区间不继续推算媒体位置；倍速使用分段速率；seek 不跨段插值；录音开始到权限/设备就绪的时间不算已采集音频。没有测得硬件延迟时诚实报告不确定区间，不伪造校准精度。
4. 实现本地、用户主动开始的实机联合测试入口，展示预计记录的事件与停止/保存方法。需要硬件偏移验证时提供可执行的标记音/回环测量方案，区分采集偏移、输出与声学传播延迟，报告误差分布及测量限制。先完成模拟/合成路径，再请求一次必要实机操作。
5. 自动覆盖权限拒绝/设备错误/轨道结束/切换与部分数据保存；实际系统权限提示、物理断开和耳机/外放听感仅由用户操作确认。正式 ASR 服务选择与录音自动清理默认仍留 Q-05 原截止点。

验收：误差报告包含样本、时钟来源、预期/实际位置、样本量及失败边界；缺少物理测量时保留对应 not-run，不把软件模拟标成硬件校准通过。当前未决定定位容差时，先给实测和推荐，不擅自承诺精确到某个毫秒。

### R4：媒体实际可用范围

1. 复用已有 FFmpeg/ffprobe 固定样本。对 MP4/H.264/AAC、候选 MKV/HEVC/ASS/多音轨、分数帧率/VFR/非零流起始时间分别记录：能探测、能在实际后端播放、字幕/选音轨行为、切分/拼接结果。FFmpeg 解码成功不能替代 Electron 播放成功。
2. 在 Electron 中完成最小播放验证；用带帧号和音频标记的合成素材校验时间基、字幕时点与音画同步。记录实际后端、构建版本、限制和许可/打包影响；无需承诺全部编码可用。
3. 无转码裁剪记录请求切点、实际首/末时间和关键帧约束；兼容拼接探测输出时间线，不兼容输入明确拒绝且保留源文件。不能仅按后缀判定兼容。
4. 图片目录/CBZ 用合成图验证排序/重复、左右阅读、长图、旋转和大尺寸的最小显示/资源预算；不实现完整漫画产品。损坏/超预算输入需可解释失败，不阻塞 UI。
5. 汇总为“已验证支持 / 已验证拒绝 / 未验证”的精确矩阵，给出首轮建议范围。必需范围若无法满足，保留阻塞并提出具体取舍；额外格式无需为了表格全绿而全部实现。

### R5：运行时、真实进程边界和范围契约

1. 在现有 SDK/kernel/IPC 上补一个模块的 service 与 UI Facet，加实际解析 worker。验证停用同时撤销贡献和任务、晚到消息不写入、重连或丢序后读取快照、worker/服务退出后请求不悬挂。使用真实跨边界通信，不用同进程模拟取代证据。
2. 最小 UI 和假 Agent 调同一应用命令；有限授权由可信宿主发放/检查，不能相信 renderer 自报 scope。测试过期/跨范围/版本冲突、旧 epoch、取消与提交屏障，以及停用后工具不可发现/不可调用。不需要真实模型。
3. 补齐 required/optional、single/many、显式关闭、Bundle 冲突、增删依赖/换源、失败回退/重启恢复；保留既有 50 次启停及资源计数验证。复杂图或代码变化允许按契约要求重启，界面/诊断须如实表达生效状态。
4. 同一契约和故障输入跑三个小场景：阅读器停用后资料保留与恢复、双假数据库换源、加入下载组合导入后再移除。核对身份、用户数据和清理结果。
5. 对候选做有意义的契约/维护评估，记录一次小型契约演进、兼容或拒绝策略、依赖版本核查及故障定位过程。必要时做最小适配候选；没有固定完整候选数量。明确哪些只做了静态研究、哪些运行过，不以故意泄漏的反例证明选型优越。

验收：有真实进程/Facet 时间线、资源残留计数、恢复结果及维护记录；生产建议只推荐一个满足必要契约的实现。可信实验不是第三方安全隔离证明。

### R6：关联确认、来源快照与资料包往返

1. 复用两个固定假提供者、独立 Work/Resource 身份及现有字段覆盖模型；补显式确认候选关联和冲突处理。跨媒介/续季/同名歧义不自动合并。
2. 字段及关联保留来源/版本/快照依据，用户锁定字段在刷新、空结果、超时/限流、换源或停用后保持。离线本地编辑可用。
3. 包含 Work、资源关系、原始来源快照、用户覆盖、未知对象和附件的资料包实际导出→干净 Profile 导入；在提供者停用或缺失时仍能查看保存资料。
4. 核对稳定身份/引用、附件哈希、来源字段和覆盖意图；处理包损坏、缺附件与重复导入策略，失败不能半覆盖目标库。原型优先使用隔离空目标，现有恢复禁止覆盖非空目录的保护保持。

验收：自动化用完整包往返证明资料语义保留，不以单条 SQL 或查询 JSON 比较代替包协议；真实网站适配仍留 M2。

### R7：性能、证据门禁和最终审查包

1. 用当前参考机及规定规模，补需求 6.2 中未测入口：真实 UI 反馈、轻量位置/选区上下文、已索引 TXT/EPUB 首屏、录音状态/设备错误反馈、阅读/播放进度持久化。现有检索/启动/保存结果按影响重跑；不降低原目标。
2. 区分进程冷启动/系统缓存状态、DOM 更新/可见窗口渲染、索引就绪/重解析、本地反馈/设备就绪。p95 使用预先固定场景与足够样本（重复型建议至少 30 次），保存原始值、样本量和统计方法；一次测量不能写成 p95。首屏是可操作的代表性正文，不是加载占位或固定预览。
3. 按最终源码指纹重跑适用检查、完整 POC、package、bench、report。所有必需依赖具备后再做最终全量轮次；途中用定向测试迭代，避免无意义反复构建。

## 4. 人工与决定边界

| 事项 | 当前是否阻塞工程开始 | 最终处理 |
| --- | --- | --- |
| 微信输入法、键盘与三档缩放 | 否，已报告通过 | 编辑器/布局改动影响时，仅针对变更后的行为复测 |

## 5. 收尾判定

- **工程可交审**：R1—R6 的可自动工作已实施并验证，R7 的测量、门禁、文档和具体建议齐全；剩余项只有明确的物理操作或决定，不把缺代码归给人工。
- **M0 可退出**：交付正本的关键验证有可审查结果，阻断缺陷处理完，必需实机证据和 M0 对应正式决定完成，首发平台/格式/性能/组合运行时已定稿。
- **M1 分阶段交付**：按交付正本分别核对 M1a 的 Agent/配置基础门槛与 M1b 的阅读/编辑/录音门槛。范围顺序已确认，独立实现可继续；M0 自动化全绿不代表 M1 产品已验收。

若结束时仍不满足，应列出具体未完成子项、原因、责任人和下一动作。不得以重新命名阶段、放宽既有目标或要求用户“再全面测试一遍”掩盖工程缺口。
