## 1. 责任与依赖

拥有粗剪序列：项目里的一条片段列表，每个片段指向视频资源的一个修订版和用户要的一段时间（请求区间），以及片段之间的顺序、片段的备注和序列自己的撤销历史。导出时按计划把各片段的流复制出来再接成一个新文件。不拥有视频文件与媒体信息（归视频模块与媒体服务），不改动、不复制源视频；序列里只有时间和对修订版的指向。

Feature `roughcut`；Facet `service`/`ui`；硬依赖 `manga.projects`，可选依赖 `manga.video`：序列是视频时间的列表，视频模块关闭时序列照样可读、可编辑，只有播放片段预览要等它；导出只需要媒体服务里的 ffmpeg 与 ffprobe，不需要视频模块开着。

**无转码。** 导出只复制压缩数据，不解码、不重编码，所以画质与音质不变、速度取决于磁盘；代价是起点只能落在关键帧上。因此计划（`roughcut.plan`）必须先说清“请求了什么、实际会切什么”：起点退到请求起点处或之前最近的关键帧，终点进到请求终点处或之后第一帧；实际区间永远包含请求区间。能不能切、能不能接，只由源文件的帧时间与关键帧时间和流参数判断，不解码。

## 2. 数据与公开能力

- 数据：`rough_cuts`（标题、所属项目）、`rough_cut_clips`（序列、资源、修订版、起止毫秒、排序键、备注）、`rough_cut_exports`（导出记录：状态、计划快照、结果、临时名、最终文件名、错误）。排序键与导图共用分数索引：移动一个片段只重写这一行。每个序列最多 200 个片段，每个项目最多 100 个序列。
- 编辑（`roughcut.edit`）的步骤：`add`（指定资源与区间，不给修订版取最新修订；可指定位置）、`update`（改起止与备注）、`move`、`remove`。一次调用是一次撤销，逆与变更一起保存，重启后仍可撤销与重做。区间必须落在视频范围内（终点在最后一帧之后 1 秒内仍允许，因为结尾处做的标记可能略超过最后一帧的时间），起点小于终点；不合格的步骤使整个调用不生效，连撤销历史也不变。视频被删除的片段保留并标为不可用，计划里说明，而不是悄悄缩短序列。
- 计划（`roughcut.plan`）：对每个片段给出请求与实际的起止、两端移动了多少、起点是否本来就是关键帧、会含多少视频帧、是否一直剪到文件结尾，并检查这些片段能否无转码相接。不能相接时列出问题，每一条都说明哪个片段、哪一项不同：`empty`（序列为空）、`source-missing`、`no-video`、`range`、`no-keyframe`，以及流参数的差异 `container`、`video-codec`、`video-profile`、`resolution`、`pixel-format`、`frame-rate`、`time-base`、`audio-codec`、`audio-format`、`audio-tracks`。有问题时不导出，界面不提供导出按钮。成品的容器取第一个片段的容器，只在复制能写入时使用相同的扩展名。
- 导出（`roughcut.export`，参数为序列、宿主对话框选出的目录句柄和可选的文件名）：先在应用的暂存目录里把每个片段复制出来（`cutting`），再接成一个文件（`joining`），再对成品核对（`checking`：时长与帧数与计划是否相符、流是否仍与第一个片段一致），通过后才在所选目录里先写临时名、再改名放进去（`placing`），从不覆盖已有的文件，重名时用下一个空闲名字。核对时长允许的偏差是 100 毫秒再加每个片段 80 毫秒（每个片段末尾可能多带一小段超出最后一幅画面的音频）。核对不符时什么都不留下，只留一条失败记录。导出可以取消，取消、失败与中断后目录里没有临时文件，暂存目录被清掉，序列可以继续编辑再导出。
- 通知与记录：每一步以通知报告进度；成品只以文件名出现，从不以所在路径出现；日志只记录序列的创建、改名与删除（按标题），不记录每次编辑。

### 关键帧、轨道、分段导出与章节（A-84）

- **选项：** `RoughcutOptions` 有 `mode`（`merge` 合并成一个文件、`separate` 每段一个文件）、`audioTracks`、`subtitleTracks`（要保留的轨道序号，缺省为全部）与 `chapters`（合并时把每个片段写成章节）。`roughcut.plan` 与 `roughcut.export` 都带这组选项，计划显示所选轨道与分段后的兼容性与实际区间。
- **关键帧：** 有帧时间表时，时间轴画出关键帧刻度，`rc-key-prev`/`rc-key-next` 跳到上一个、下一个关键帧；切点吸附到关键帧，可以关闭（`rc-snap`）。仍是无转码，不能静默转码；只重编码片段开头的“智能剪切”登记为后续 loop。
- **去向：** 不给文件夹时，导出写进作品内容文件夹的“粗剪”目录（`work_files` 记一条），也可以另选文件夹。
- **详情：** 导出详情显示实际执行的 FFmpeg 参数，本机路径经脱敏。
- **限制：** 多个片段合并的 ASS 字幕不带内嵌字体。

## 3. Agent 与界面

命令在同一个网关注册，界面经这一入口调用。Agent 在本项目的会话里可以读粗剪（`roughcut.list/get`）；编辑与导出仍是所有者命令（A-73）。跨项目的调用在命令层被拒绝（`creative/agent-access.ts`），不只是不在工具清单里；娱乐模式的全局对话与资源会话没有这些命令；仍只由所有者操作的部分登记在[执行状态](../delivery/status.md#loop-09)。界面：项目页的“粗剪”标签，左侧序列列表，右侧是片段列表（片段的标题、请求区间，可直接键入时间；上下移动；备注；移除；预览所选区间）、总时长、检查结果（每个片段的请求与实际区间、移动了多少秒、问题清单），以及导出区（选择目录与文件名、进度、取消、历史记录与每次的核对结果和用时）。导出过程中序列被锁定，不能编辑。序列改动后过一小会儿再重新检查，不在每次按键之后检查。播放器里有“加入粗剪”：有标记的区间就加标记，没有标记就从当前位置起取几秒，目标序列可以就地新建，必要时连项目也就地建一个。

## 4. 生命周期与兼容

停用：命令撤销，序列与历史保留；运行中的导出被停止并标明原因。应用在导出中途退出：下次启动把那条记录标为被中断，并清掉它留下的临时文件与暂存目录。序列随项目包与资料包往返（修订版 ID 按资源重映射）；撤销历史属于 Profile，不进包。迁移前自动备份，失败回滚。视频模块关闭不影响序列，也不影响导出。

## 5. 验证与未决

自动：`tests/creative/roughcut-plan.test.ts`（切点、流兼容）、`roughcut.test.ts`（AT-32）、`roughcut-export.test.ts`（AT-33：真实 ffmpeg 生成的合成视频，覆盖关键帧与非关键帧起点、多个来源与同一来源两次、剪到文件结尾、不同容器、安全文件名、不覆盖、取消、核对不符、来源消失、被中断、模块关闭）、`tests/shell/roughcut-ui.test.tsx`。窗口：`creative-roughcut-export`（打包应用里对合成视频导出，逐帧核对成品帧数与计划一致）。基准：`roughcutOverheadMs`（导出总用时中不属于媒体工具的部分），见[执行状态](../delivery/status.md)。

限制：起点只能在关键帧上，所以含开放式 GOP 的源在起点处可能带有引用前一组画面的开头图像，已在计划中以请求与实际区间的差表现，但播放器是否显示它们取决于播放器；各片段的参数集（序列与图像参数集）以哈希比较，接起来后以带内参数集出现的变化不检查；只取第一条视频流；音轨与字幕轨默认全部保留，也可以只选其中几条（没有选音轨时各片段的音轨数必须相同；图像字幕放不进 MP4 与 MOV），数据流与元数据不保留，章节只在合并导出且勾选时由各片段生成；容器随第一个片段，不能转封装为别的格式；没有转场、没有变速、没有多轨时间线。
