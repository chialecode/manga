## 1. 责任与依赖

拥有“获取”：从一个来源（磁力链接或种子文件）经某个引擎取得文件，放进用户已经授权的资源库路径，并让库把它们读成资源。引擎只负责搬运字节并如实报告发生了什么；放在哪里、够不够地方、失败意味着什么、重启怎么办，全由本模块决定。已入库的资源不依赖下载插件：引擎被停用、卸载，已经入库的文件与作品照常可读（AT-42），也没有任何从阅读到下载的反向依赖。

Feature `acquisition`；没有自己的界面部分（页面由引擎插件的 `acquisition` 界面部分提供，只在这个功能开着并且有启用的引擎时才出现，没有引擎就没有“下载”页）；模块声明没有硬依赖，运行时需要插件功能里有一个启用的、提供位置 `acquisition.engine` 的引擎，入库用资源库的扫描。关闭本功能把所有运行中的下载暂停，不丢任务。

**引擎协议。** 本模块通过插件运行时调用引擎的方法：`engine.info`、`configure`、`limits`、`add`、`select`、`seed`、`remove`、`status`；引擎以 `acq.*` 事件报告元数据、进度、校验与结束。引擎在应用给它的目录之外不保存任何东西，所以应用能在停止或崩溃之后把同一个任务再次加入。引擎的断点格式（`resumeFormat`）记在任务上：换了引擎、格式对不上时不拼接别人留下的东西，任务以 `RESUME_INCOMPATIBLE` 停下，由用户选择从头重新开始（`acquisition.restart`，已在库里的文件不受影响）。

## 2. 数据与公开能力

- 数据：`acquisition_jobs`（来源种类、来源引用、信息哈希、名称、状态、所在阶段、库路径、子目录、预算、已选/已下/已传字节、做种设置、错误、纪元）、`acquisition_entries`（每个文件的序号、路径、长度、是否选中、是否校验、指纹、发布状态、目标相对路径、入库状态、资源 ID、备注）、导入回执。暂存区 `<staging>/<jobId>/{data,engine}` 与保存下来的 `source.torrent`；来源引用不出现在任何视图、通知与日志里（磁力里可能带有 passkey）。
- 流水线与状态：`metadata → choosing → downloading → verifying → publishing → importing → done`，另有 `paused`（用户暂停，或引擎消失；记录原因与暂停前的位置）、`failed`（记录停在 `transfer`、`publish` 还是 `import`，以便给出对应的重试）、`cancelled`。每一步在做之前先写下来，所以每一步都可以在崩溃后重复，并走到同一个结果。
- 添加（`acquisition.add`）：来源是磁力链接，或用户在宿主对话框里选的种子文件（最大 8 MiB，复制进任务自己的目录）；必须指定一个已有的库路径和可选的子目录（只允许相对、安全、写得进每个系统的文件夹名）；预算可设最大字节、下行与上行速度，0 或不填表示不限。同一个信息哈希已有任务时拒绝。元数据到手后任务停在 `choosing`，由用户在种子的文件清单里选要哪些文件（`acquisition.select`）；选中的总字节超过预算以 `QUOTA_EXCEEDED` 拒绝，选中的文件加 64 MiB 余量超过目标卷可用空间以 `DISK_FULL` 拒绝。种子里每个文件的路径宿主自己再检查一遍（绝对、`..`、保留名一律拒绝），不信任引擎已经检查过。
- 校验：引擎对每个分片按种子里的哈希校验，不合格的分片丢弃重下；文件完成后宿主再算一遍整个文件的 SHA-256 作为指纹，之后的发布与入库都对着这个指纹。
- 发布（`publishing`）：暂存的文件先完整并校验，再在库路径下以最终名一步出现，之后才放掉暂存的那份；从不覆盖已有的文件。同卷用硬链接（不复制），跨卷先复制到目标旁的临时名，刷盘、与指纹核对，再链接或改名放进去；目标名被占用时看占着的是不是同一个文件（长度与指纹相同，则采用，不重复），否则取下一个空闲名 `name (2).ext`，找不到空名以 `PUBLISH_CONFLICT` 停下。崩溃在发布中间，下次从留下的状态接着做：只会留下一个带点前缀的临时文件，会被找到并清掉。
- 入库（`importing`）：对该库路径做一次扫描（扫描已经在走时会补扫一次），再把每个已发布文件与库里的记录对上，写下它成了哪个资源，或为什么没有（`not-recognized`、扫描报的错误）；所有选中的文件都读成资源后清掉暂存并标 `done`。下载成功而入库失败时只重试入库（`acquisition.retryImport`），发布失败时只重试发布（`retryPublish`），不重新下载。
- 暂停与恢复：暂停让引擎移除这个任务但保留文件，恢复时重新加入，由引擎对已有的文件重新校验后接着下；应用退出后，仍在传输的任务在下次启动时标为因引擎而暂停；因引擎而暂停的任务在引擎重新运行时自动继续（引擎的断点格式对不上的除外），用户自己暂停的不会被自动恢复。取消（`cancel`）删除暂存，不动已发布到库里的文件；移除（`remove`）只删除任务记录。
- 速度限制：每个任务的下行与上行限速取所有运行中任务里最严格的一个，应用于引擎的整个客户端（引擎的限速是全局的）。
- 做种（`acquisition.setSeeding`）：默认关闭；只有完成后，且每个选中的文件都在种子期望的位置与名字上（发布时没有改名、没有加子目录之外的偏移）才可能做种，否则以 `seed-impossible` 拒绝；可设分享率与上行速度，到达分享率后自动停止并通知。

## 3. 联网与权限边界（ACQ-03）

下载是用户发起的动作，本模块不提供给 Agent：这些命令是所有者命令，不在 Agent 的工具清单里，资料查询的权限也不会扩大成下载（AT-47）。目标目录只能是用户已经授权的库路径下的相对位置，路径越界、保留名一律拒绝。引擎进程自己连网、读写文件，不经宿主的门；因此引擎只能是受信任发布者签名的插件（见[插件模块](plugins.md)）。第一方 BitTorrent 引擎在应用里的默认行为：

- 联网：加入 DHT；本地节点发现、UPnP 与 NAT-PMP 默认关闭；只用普通套接字能到达的 tracker（http 与 udp）；**关闭** WebRTC、web seed 与 uTP；每个种子最多约 55 个连接。测试与窗口检查里网络只放在回环地址上，不接触公共 DHT 与 tracker。
- 随包与依赖：引擎源码在 `plugins/acquisition-bt/`，构建时打成一个文件并由第一方私钥签名后放进安装包（`resources/plugins/`，安装包里只“提供”，用户在设置里自己装上）；主要依赖 webtorrent 3.0.21（MIT）与 bittorrent-tracker 11.2.3（MIT），加上它们的传递依赖共 122 个包，许可证只有 MIT、Apache-2.0、ISC、BSD 与 BlueOak；WebRTC 的原生库 `node-datachannel`（MPL-2.0）与 uTP 的原生库被构建时替换为空桩，不进入安装包。
- 日志与脱敏：日志只含任务名与状态，不含磁力链接、passkey、tracker 地址与文件所在位置；窗口检查专门断言页面、任务视图与日志里都找不到磁力里的密钥（`magnet-secret-never-shown-or-logged`）。

## 4. 界面

设置里装上并启用引擎之后，主导航出现“下载”页：添加区（粘贴磁力链接或选种子文件、选库路径与子目录、可选预算）、任务列表（名称、状态、进度、速度、已选文件）、选文件的清单（逐个勾选、显示总大小，超出预算与空间不足的提示）、每个文件发布与入库的结果、失败停在哪一阶段与对应的重试按钮、暂停/恢复/取消/移除（取消与移除先问，说明会保留什么）、做种开关与设置。引擎被停用时页面说明任务因此等待，并让手动恢复保持不可用，直到引擎回来；各种拒绝都被翻成人话。键盘可完成全部操作。

## 5. 生命周期与兼容

停用本功能或引擎：运行中的任务暂停（原因 `engine`），记录与暂存保留；引擎重新运行后这些任务自动继续，用户自己暂停的任务不被自动恢复。卸载引擎：任务保持暂停，已入库的内容不受影响；换成另一个引擎时断点不兼容，提示重新开始。任务记录在应用数据库里，暂存与种子文件不进资料包。迁移前自动备份，失败回滚。

## 6. 验证与未决

自动：`tests/acquisition/engine.test.ts`（引擎本身在回环蜂群上：元数据、选文件、校验、限速、做种）、`bt-e2e.test.ts`（经插件进程的完整下载）、`host.test.ts`（引擎要什么与宿主拒绝什么、选文件与预算与空间、发布中途崩溃、真实跨卷发布、暂停与引擎消失、做种）、`tests/shell/downloads-ui.test.tsx`；回环蜂群由 `tests/helpers/bt-swarm.ts` 在独立进程里起，磁力里带 `?passkey=` 用来验证它不泄漏。窗口：`plugins`（见[插件模块](plugins.md)）里的下载部分：在打包应用里经页面从回环蜂群下载、选文件、发布、入库为作品、暂存清空、磁力密钥未出现。基准：`btLoopback`（本机回环 200 MB 下载，读回成品核对所有分片哈希，未校验分片数必须为 0；记录吞吐），见[执行状态](../delivery/status.md)。

限制：没有在公共 DHT 与真实 tracker 上测过；WebRTC、web seed 与 uTP 关闭，所以某些只能经 WebRTC 或 web seed 到达的来源取不到；速度限制是引擎客户端范围内取最严格的一个，不是按任务分别限制；只支持磁力与种子文件，不支持 HTTP 直链与其他来源；Agent 目前不能添加或管理下载；没有计划任务与带宽时间表；做种要求文件保持下载时的位置与名字，用户改名或移动后需要重新下载校验才能做种；真实资源的版权与来源合法性由用户负责，应用不提供任何来源。
