# ADR-0002：本地验证优先的 GitHub 协作

| 字段 | 内容 |
| --- | --- |
| 状态 | accepted：仓库、CI 和单人维护规则按本次授权采用 |
| 日期 | 2026-09-19 |
| 决定来源 | 用户要求建立 Git/远端管理，以本地验证为主，保留必要 CI 并减少高频自动化；随后确认单人维护 Ruleset 与仅准备 GitBook 配置 |
| 范围 | 版本历史、分支、验证、Actions 权限、低频协作及 GitBook 准备 |

## 背景与选择

MANGA 仍处于设计和 M0 准备阶段，只有文档治理脚本，没有应用构建或发行物。维护者曾遇到账户反 spam 审查，因此需要控制无效推送、重复 CI 和自动化写入，而开发过程仍须具备可重复验证与受保护的主分支。

选择本地统一验证入口、一个轻量 GitHub workflow 和单人维护 Ruleset。CI 使用 PR 事件和手动运行，不同时对 main push 重复验证，不设置定时全量任务。保护要求 PR、真实必需检查和讨论解决，审批人数为 0；不要求不存在的协作者，不给自动化永久绕过权限。

仓库从独立空历史建立，第一个提交只含空 README；现有文档和配置在后续提交进入历史。根 README 的最终正文保留。GitHub 仓库为 `chialecode/manga`，默认分支为 `main`。

## 集成范围

- GitBook：用户确认只准备内容配置、阅读目录及接入说明，本次不连接或发布。
- Bot：维护实现采用已提出的低频默认方案：仅 GitHub Actions 的 Dependabot 每月分组更新、最多一个未关闭 PR、关闭自动 rebase；这是本次仓库配置范围内的技术选择，不记为用户另行确认。不安装有评论权限的第三方 App，不启用自动安全修复 PR。
- 安全：保持密钥扫描和推送保护，使用私密漏洞报告入口；许可证、贡献协议和产品发布签名继续作为独立待决事项。

## 权衡与替代方案

全量多平台 CI 当前无法验证不存在的产品，徒增配置与运行成本；将来有对应工程后再增加。只用本地 hook 无法为远端 PR 提供统一检查，因此保留 CI 和 Ruleset。强制独立审阅或 DCO 会引入尚未满足的人员/协议前提，本期不作为必需状态。

关闭“必须最新 main”减少无意义的分支更新，但维护者需要判断共享契约、依赖和迁移的并发变更，必要时更新分支重新验证。仅 PR 自动检查意味着直接修改 main 的初始化或恢复操作必须有单独验证，不能以无 CI 运行解释为通过。

## 执行与后续

操作规则见 [Git 与 GitHub](../dev-rules/git-and-github.md)，执行证据见 [建立报告](../evidence/2026-09-19-github-bootstrap.md)。CI、Ruleset、App 配置和服务端实际生效分别核验；不把 JSON/YAML 文件存在当作已经启用。

新增协作者、正式应用工程、外部贡献协议或产品发布要求时再修订相应部分。任何低频策略都不构成 GitHub 账号免于风控的保证。

## 2026-09-19 审查提交整理决定

用户明确要求减少本地 Agent 审查过程中重复修复提交和失效消息造成的审查消耗：同一交付尚未 push 的修复直接 amend 原提交，消息保持对最终结果的准确描述。不同里程碑或独立交付仍分别提交；M0 与 M1a 即使都未推送也保留各自边界。此决定替代“每轮本地集中修复均追加 commit”的节奏，实施和恢复要求以 [审查提交规则](../dev-rules/git-and-github.md#review-commits)为正本。

已推送提交默认追加修复；本次指定历史整理的授权不构成以后自动改写远端的许可。必要的本地备份、依赖衔接和复验先完成，改写后更新交接基点；历史测试证据保留原被测版本，不把整理历史写成重新测试或产品验收。
