# ADR-0001：建立 MANGA 文档治理框架

| 字段 | 内容 |
| --- | --- |
| 状态 | accepted：在本次文档建设授权范围内采用 |
| 日期 | 2026-09-19 |
| 决定来源 | 用户要求完善可指导 AI AGENTS 和程序员的 MANGA 文档管理框架 |
| 实施者 | 本次文档维护 Agent；不代表另有未记录的逐项产品审批 |
| 作用域 | 文档组织、权威、变更、追踪与本地校验，不选择应用框架 |

## 问题与候选

现有需求、设计和验收定义已较完整，但缺少统一的开发入口、专项约束、决定/执行状态台账、模板和机械检查。仅扩写 README 难以按任务查找；规则还需要明确权威范围、适用阶段和真实验证方式。

## 决定

采用“根目录入口 + 产品/开发/设计规则 + 既有需求与详细设计 + 决定台账 + 交付证据”的结构。既有 `docs/product/`、`docs/design/`、`docs/delivery/`保留，避免为目录整齐重写全部链接。

以 [文档治理](../governance/documentation-policy.md)定义职责，以 [登记表](../governance/document-registry.json)记录状态/责任，以根 AGENTS 提供按变更触发的入口。增加标准库实现的本地文档检查；不为检查虚构应用工程或远端 CI。小变更使用简短说明，重要契约和选型保留 ADR。

## 后果与验收

维护者需要在增加文档时同步登记与索引，在改变需求时同步验收映射。收益是 AI 和程序员可以区分应有行为、暂定方案与真实实现，找到唯一修改位置。

文档检查负责可机械判断的结构一致性；需求合理性、确认真实性和实际产品质量仍需要评审与执行证据。框架建立时的验证见 [证据](../evidence/2026-09-19-documentation-framework.md)。

后续调整本框架直接修订相应规则；若改变整体分层/权威模型，追加 ADR 并标明替代关系。
