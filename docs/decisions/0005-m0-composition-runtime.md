## 背景和候选

候选 A：自研 `packages/kernel`。候选 B：`MinimalActivator`（故意无屏障/无释放）。未做完整第三方微内核适配。

## 决定与理由

**正式决定**：采用自研 `packages/kernel` 作为唯一生产组合运行时。目标是 UI Facet、service 命令与解析 worker 走统一的有限授权与代次；停用撤销贡献并丢弃晚到解析。M0 固定 scope 字符串的局限由 M1a grant 接续；grant、幂等回放与实际 UI 撤销的完整验收继续，不由选型自动推定通过。

实测理由：

- 50 次启停资源计数、IPC 取消/退出、UI 与假 Agent 同一命令、跨范围拒绝、阅读器停用后资料保留、假提供者换源后快照仍可读、下载模块停用后资源身份保留。
- 真实 Node 子进程解析 worker 支持取消、退出后请求失败、库停用后丢弃晚到结果。
- `MinimalActivator` 是门禁反例，用来证明检查能失败；不能当作公平对比后“kernel 胜出”的依据。

以上实验子集不能提升为完整产品能力。2026-09-19 [复核](../evidence/2026-09-19-m0-closure-review.md)补充确定性晚到结果拒绝及 worker 重新启用回归；有限授权、真实 UI Facet、维护成本与替换边界仍需 [M1a P1](../delivery/m1a-execution-plan.md)实证。

未做：第三方插件沙箱、不可信代码隔离、完整微内核替换。可信实验进程边界 ≠ 安全沙箱。

## M1a 实证与正式决定

产品宿主继续使用 `packages/kernel`：React UI Facet、service 命令与解析 worker 走同一启停链；授权改为宿主发放的 grant（actor、会话/任务、命令、读写集合、代次、撤销）。已测 50 次启停、停用后 UI/命令撤销、越权拒绝、晚到写入拒绝、UI 与 Agent 共用命令。MinimalActivator 仍只作反例。维护成本集中在 epoch/grant 校验与热变更重启边界。2026-09-20 已获用户正式决定；与可在设置中替换的 AI runtime 分属不同层次。

维护：契约演进以模块清单/epoch 拒绝旧句柄；复杂图变化允许重启并在界面写明生效状态。依赖版本由 `pnpm-lock.yaml` 与 `scripts/check-deps.mjs` 核查。

## 后果和实施

落选实验不得进入发行依赖。M1a 按本决定继续集成与验证；最新 [A 审查](../evidence/m1a-acceptance-review.md)的安全、生命周期与恢复缺口由开发者修复，不能以定稿代替产品验收。Q-06 的第三方执行形式仍按原截止点，不提前开放。
