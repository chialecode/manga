## 背景和候选

需要验证中文输入法、块 ID、撤销、源/布局分离。比较过的方向：原生 textarea + 自研块命令；contenteditable；ProseMirror/TipTap；React/Vue 外壳。

## 决定与理由

**原推荐（已被替代）**：M1 笔记正文继续用原生 `<textarea>`，块身份/分拆/合并/嵌入走独立命令与 SQLite 文档，不把编辑器框架当作定位协议。当前生产方向已改为 React、Tiptap/ProseMirror 与对应源编辑场景的 CodeMirror 6，不能继续以本页决定新产品编辑基础。

实测理由：

- 微信输入法、美式键盘、100%/125%/150% 缩放已在 textarea 原型上获用户通过；合成 composition 守卫不能替代这次实机结果。
- 收尾 R2 用同一套 locator/blockId 完成长章全文定位、分拆/合并、循环嵌入拒绝；替换编辑器不应重写领域协议。
- contenteditable / ProseMirror 没有同等 IME 证据。若更换编辑表面，必须重做原生输入法检查，不能继承本次结论。

替代：需要复杂富文本后再评估 ProseMirror；React/Vue 只作为壳，不自动等于编辑器选型。自研范围应限于 locator、块身份、IME 守卫与持久化，不自研排版引擎。

## 后果和实施

原生 textarea 仍是现有 M0 实现及旧证据的对象。新选型尚未集成，更换编辑基础后复测输入法、选区、撤销、保存恢复和缩放；不能把本页人工结果移用于新编辑器。技术选型不同时定稿视觉 Token。
