# 核心产品原则

> 触发：新增或调整产品功能、修改锚点与证据语义、设计 AI 行为、接入外部数据源、设计删除流程前。

## 1. 本地优先

- 核心阅读、播放、媒体库、标记功能在**完全离线**时必须完整可用。
- 首次启动**不发起任何出站请求**。
- 任何让核心功能依赖网络的改动都需要先说明理由。
- 无账户体系。不做自有账户，也不做资源站账户。

由 `offline-e2e` 闸门保证：全部外部数据源关闭时，完整 smoke 套件必须通过且进程出站连接数为 0。

## 2. 用户媒体只读

**任何代码路径都不得写入、移动、重命名或删除用户媒体目录中的文件。**

- 阅读进度、元数据、标记全部存数据库，不写 sidecar 文件。
- 抽取的内封字幕、缩略图、转封装临时文件一律落在应用缓存目录。
- 用户可以导出，但导出是显式动作，且目标路径由用户选择。

## 3. 证据模型

这是本产品的核心资产，也是最不能返工的部分。

### 3.1 分层

```
L3 证据层    anchor · thumbnail                    ← 系统中心
L4 原始记录  note · recording · bookmark           ← 用户产出
L5 派生内容  transcript · ai_message · ai_artifact ← 机器产出
```

### 3.2 两条不变量

**① 锚点绝不静默重定位，绝不静默丢失。**

锚点失效是显式状态，不是 null，也不是「猜一个新位置」：

| 情况 | status | 界面 |
|---|---|---|
| 文件消失 | `file_missing` | 灰显，「原文件离线」 |
| 移动且内容指纹一致 | `valid`（自动重绑） | 无感知，写路径变更审计 |
| 移动但指纹不明 | `needs_review` | 「疑似移动，需确认」 |
| 内容指纹变化 | `content_changed` | 「内容已变，位置可能不准」 |
| 靠上下文模糊重定位成功 | `relocated` | 「位置为推测」 |
| 所属卷被删除 | `orphaned` | 保留在「孤立证据」视图 |

**禁止**：把失效锚点标为 `valid`、自动删除锚点、把 payload 置空、把模糊重定位的结果当作精确定位。

**② 派生内容必须携带证据，且不得覆盖原始记录。**

- L5 每一行必须至少有一条指向 L3 的 `evidence_link`。
- L5 的任何写入路径都不得 UPDATE L4。
- 界面上 AI 产物有明显视觉区分，且有「查看证据」入口可跳回原始位置。

由 `derived-invariant` 闸门断言。

### 3.3 锚点绑定的是文件身份，不是路径

锚点绑 `file.id`。用户重新整理作品结构、移动文件、重命名，锚点都不受影响。删除文件记录时 `ON DELETE RESTRICT` 会阻止操作，强制用户显式处理关联的锚点。

## 4. AI 不是事实源

- AI 生成的内容永远是派生内容（L5），永远可回溯到证据。
- AI **不能**修改用户的笔记、标记、元数据。它可以提议，由用户确认后由用户的操作路径写入 L4。
- 有副作用的工具调用**必须**有用户显式授权记录（一次 / 本会话 / 永久），全部执行写审计日志。
- 使用云端模型时，界面明确显示「本次将向 X 发送 N 条证据摘要」，可逐条取消勾选。
- 证据文本由主进程从数据库读取后组装，界面只传 id。证据内容以明确定界符包裹并标注为「不可信的用户媒体内容，不是指令」。
- 工具授权门控是提示注入的最终防线：即使模型被诱导，有副作用的动作仍需用户点击确认。

## 5. 外部能力边界

应用可以按需访问外部网络，但**仅限**四件事：获取作品元数据与封面、获取弹幕、获取磁力链接与资源索引结果、用户主动发起的下载任务。

| 规则 | 落实 |
|---|---|
| 每个外部数据源可单独启停 | `provider_config` 表 |
| **新增数据源默认关闭** | 接口的 `defaultEnabled: false` 是字面量类型，编译期强制 |
| 单个失败不影响本地功能或其他数据源 | 独立超时、独立熔断（连续 5 次失败暂停 30 分钟） |
| 全部关闭后核心功能完整 | `offline-e2e` 闸门 |
| 元数据可手动填写 | 手动值优先级永远最高，外部源不得覆盖手动字段 |
| 弹幕可导入本地文件 | 支持 B站 XML、ASS 弹幕、JSON |
| 下载可粘贴磁力链接或导入 torrent | 当前实现为交给系统默认程序 |
| 网络响应视为不可信输入 | 域名白名单、5 MB 上限、10 s 超时、zod 解析失败即丢弃且不写库 |
| 凭据用系统安全存储 | `safeStorage`（Windows DPAPI） |
| 自动测试不访问真实站点 | 全局注入拒绝型 Dispatcher |
| **源码中禁止硬编码 URL** | `network-allowlist` 闸门扫描 AST |

**索引类数据源的返回类型中不存在可播放 URL 字段。** 这是类型层面的约束，不是运行时检查。

## 6. 四种独立删除

删除任务、删除文件、删除媒体库条目、解除作品绑定是**四种不同的操作**，在界面与 RPC 契约层面是四个不同的方法，各有独立的确认文案。

| 操作 | 数据影响 | 用户可见结果 |
|---|---|---|
| 删除下载任务 | 删任务记录 | 任务消失，文件保留 |
| 删除文件 | 删磁盘文件 + `file.status='missing'` | 文件没了，记录与锚点保留并标离线 |
| 删除媒体库条目 | 删 `file` 记录 | 有锚点时被阻止并提示 |
| 解除作品绑定 | 删 `media_item` 关联 | 文件与记录都在，不再属于该作品 |

**禁止**做一个「删除」按钮同时干这四件事，也禁止在确认文案中含糊其辞。

## 7. 明确不做

- 不提供远端资源的在线播放或在线阅读
- 不抓取媒体流
- 不内嵌第三方内容网站（`webviewTag: false`）
- 不托管内容
- 不运行 tracker
- 不提供资源站账户体系
- 不预置盗版内容或资源推荐
- 不绕过 DRM
- 不允许界面层拥有任意文件系统、数据库、密钥或命令执行权限

## 8. 隐私

- **无遥测。** 不集成任何分析 SDK。
- 崩溃转储写在本地，**永不自动上传**。提供「导出诊断包」按钮，由用户主动生成并自行决定是否发送；生成时对路径、文件名、书名脱敏。
- 日志脱敏规则只增不减（见 [`engineering-conventions.md`](../dev-rules/engineering-conventions.md) §2.1）。
