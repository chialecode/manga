# MANGA 界面实现与设计治理

触发：页面、组件、布局、样式、动效、文案、主题或设计基础变化。已确认方向为简洁白灰粉、默认三栏和主内容优先；详细流程与候选尺寸/色值的唯一正本是 [界面与工作流](../design/interaction-and-workflows.md)。本文不另建颜色表。

## 1. 设计依据与值的所有权

变更先引用需求/流程和适用章节，说明用户目标、状态与可访问路径。原有色号、宽度和最小窗口是初始建议值，未经实测/决定不标“已定稿”。框架、组件库、深色主题与首发语言范围见 [待决事项](../decisions/open-questions.md)。

首次实现时建立语义 Token 和共享组件：基础值→语义用途→组件消费，避免业务页面散落同义裸色/尺寸。确定代码数值正本后，在交互文档标明接管范围并链接实际文件；可生成摘要，不同时手工维护两张精确数值表。内容素材固有颜色、用户阅读偏好等例外说明用途与范围。

主题与发布语言范围由产品决定，所有实际承诺的主题、缩放和窗口范围都需要验证。用户阅读样式与应用壳品牌主题分别管理。

## 2. 组件与完整状态

- 优先复用现有组件；增加新模式说明为什么现有组件无法表达。组件 UI 名称表达用户任务，IPC、epoch 等内部术语留在诊断详情。
- 页面按适用情况覆盖空、加载、可用、部分成功、错误、离线、权限不足和模块缺失；执行动作区分保存中/已保存、取消请求中/已停止、文件下载完成/入库完成。
- 隐藏侧栏仍保留任务/录音状态和停止入口；模式/页面切换不改变异步任务目标，不丢已确认保存的内容。
- 来源、实时引用、快照和复制有可识别行为；缺失引用保留描述与恢复入口。

## 3. 可访问性与中文输入

核心流程提供键盘路径、可见焦点、浮层退出和焦点恢复；颜色不是唯一提示。沿用交互设计的正文对比度目标，实际检查状态组合。输入法组合期间不能提交、触发全局快捷键或被 AI 更新覆盖。

窄窗按实际可用宽度折叠/抽屉处理，主要操作必须可达；检查高 DPI、文字缩放、长标题、空数据和长错误。减少动态效果偏好生效；阅读内容避免因后台进度更新反复跳动。

## 4. 证据与变更完成

有 UI 实现后，报告标明应用版本/快照、平台、视口、缩放、主题、样本和实际检查步骤；截图须对应本次最终内容，必要时包括正常和关键失败状态。静态 HTML/设计图能验证布局设想，不能替代 Electron 的真实键盘、输入法、保存和任务流程。

纯文案纠错不必建立完整视觉报告；影响布局、组件、主题或完整交互的变更留下相应证据。做不到实机验证时明确哪些未测，不以“用了 Token”声称已验证。对应 AT-01、AT-10、AT-13、AT-16 及相关页面用例。
