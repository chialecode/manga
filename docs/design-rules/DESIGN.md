# MANGA 界面实现与设计治理

触发：页面、组件、布局、样式、动效、文案、主题或设计基础变化。已确认方向为简洁白灰粉、主内容优先、单一工作区（顶部一行含菜单与窗口按钮、图标栏、侧栏、标签页与分屏的主区、右侧对话停靠栏）、窄窗时侧栏与停靠栏收为浮层；详细流程与候选尺寸/色值的唯一正本是 [界面与工作流](../design/interaction-and-workflows.md)。本文不另建颜色表。

## 1. 设计依据与值的所有权

变更先引用需求/流程和适用章节，说明用户目标、状态与可访问路径。原有色号、宽度和最小窗口是初始建议值，未经实测/决定不标“已定稿”。框架、编辑和组件基础按 [ADR-0007](../decisions/0007-technology-stack.md)选定；首版中文并保留多语言扩展；主题数量与 Token 仍见 [用户待办](../../USER-ACTIONS.md)。

首次实现时建立语义 Token 和共享组件：基础值→语义用途→组件消费，避免业务页面散落同义裸色/尺寸。确定代码数值正本后，在交互文档标明接管范围并链接实际文件；可生成摘要，不同时手工维护两张精确数值表。内容素材固有颜色、用户阅读偏好等例外说明用途与范围。

已授权先实现可替换的临时主题和可选字体方案（A-25），最终主题范围仍待评审；中文 UI 已确认，所有实际承诺的主题、缩放和窗口范围都需要验证。用户阅读样式与应用壳品牌主题分别管理。

具体间距、候选色值、组件布局等在已确认方向内先实现可调整版本，完成状态、键盘和布局自检后集中提交真实界面证据；不逐组件询问偏好。确实改变工作流或功能含义时按[连续执行流程](../dev-rules/development-workflow.md#continuous-execution)判断阻塞范围，未定数值不能写成用户已确认。

A-35 的界面基础为 React + Tailwind CSS + shadcn/ui，按实施时最新稳定版本验证，Tailwind 不限定主版本。shadcn 组件源码纳入仓库维护；引入、定制、升级均保留可访问性和业务状态。Figma 建议先对齐核心流程、关键状态与响应式布局，再与功能按完整切片迭代；不要求先画完整应用才开始，也不把 UI 全留到功能之后。具体约定见下文“设计与实现约定”；组件拆分与按参考图重做界面已完成，最终视觉由 Q-08 评审。Figma 和 shadcn 集成均不能由该决定推定为已经完成。

### 设计与实现约定

1. 工作流与状态以需求和[交互设计](../design/interaction-and-workflows.md)为准；Figma 帧（如启用）标注对应流程、状态、视口和组件 variant，给出操作结果，而不是只有一张静态图。
2. 原始值 → 语义用途 → 组件消费。由 `apps/desktop/src/renderer/styles.css` 单源管理代码 token；Figma 使用对应语义名，变更时核对差异。组件规模确有需要时再引入 DTCG JSON/生成器并增加一致性检查，不能把“准备采用”写成已自动同步。
3. shadcn 源码落库后由项目维护：记录 CLI/registry 来源与版本，升级时查看上游 diff，保留本地可访问性、中文与 Electron 修复，禁止批量覆盖定制组件。
4. 浮层行为显式建模为关闭、临时展示、关闭缓冲、固定等状态，门户内容与焦点也属于可操作区域；只用 CSS hover 不能替代键盘与触屏路径。
5. 标签页与分屏的视觉规则（[交互设计 2.6](../design/interaction-and-workflows.md#26-标签页与分屏)）：标签条高约 32 px，与 36 px 的顶部一行用线分开；分屏库的 `--dv-*` 变量全部映射到语义 token（`styles-frame.css`），深浅主题不另设色号；获得焦点的栏用强调色的细上边，非焦点栏不加任何边框或卡片；栏与栏之间只有 1 px 的分隔线；拖动标签时只显示落点（栏内、栏边形成新栏），超过 4 栏时栏边不出现落点；标签的图标表示类型，标题截断时悬停显示全名；标签条、侧栏树、图标栏与栏的切换按钮都有可访问名称并能用键盘到达，焦点在栏之间移动时有可见的焦点环。
6. 原生窗口与编辑交互以最终 Electron 包为准；设计稿不承担保存确认、输入法、授权或来源身份的正确性验证。最终主题、密度与尺寸按 Q-08 集中确认。
7. 先形成核心流程与视觉基线，再按完整切片（正常、失败、恢复、窄窗）逐步实现；既不先做全部功能再补界面，也不等待全应用高保真图。切片完成前用最终包核对宽窗、窄窗、矮窗、键盘、真实输入法、系统缩放和减少动效偏好。
8. 侧栏色（A-99、A-102，语义 token `--color-sidebar`）：介于窗框色（顶部一行与图标栏）和主区的页面色之间，侧栏、悬浮卡片与设置目录共用，组件不得另写色号。浅色主题窗框 `#F3F4F7`、侧栏 `#F9FAFB`、页面 `#FFFFFF`；深色主题窗框 `#14171F`、侧栏 `#1A1D27`、页面 `#1F232E`（深色里页面比窗框亮，侧栏仍严格在两者之间；这组值已备好，由窗口观察在根元素上打上 `data-theme="dark"` 核对，应用里还没有选深色的设置，主题范围待 Q-08）。侧栏上的对比度（`tests/shell/sidebar-tokens.test.ts` 逐项断言）：正文色 ≥ 7:1（浅 11.5、深 13.9）、次要文字与图标 ≥ 4.5:1（浅 4.7、深 6.7）、卡片边线 ≥ 1.1:1（浅 1.21、深 1.48）；侧栏与窗框、与页面各自至少差一个可见的台阶（对比度 > 1.01，实际 1.05—1.07）。行的悬停底色用 `--color-muted`，不等于侧栏色。悬浮卡片有 1 px 边线与阴影，读作浮在页面上；设置页本身是页面色，不是侧栏色。

## 2. 组件与完整状态

- 优先复用现有组件；增加新模式说明为什么现有组件无法表达。组件 UI 名称表达用户任务，IPC、epoch 等内部术语留在诊断详情。
- 页面按适用情况覆盖空、加载、可用、部分成功、错误、离线、权限不足和模块缺失；执行动作区分保存中/已保存、取消请求中/已停止、文件下载完成/入库完成。
- 窗口按钮（最小化、最大化或还原、关闭）由应用绘制（A-91），颜色只来自语义 token：文字色、悬停与按下用文字色与透明的混合、关闭按钮悬停与按下用危险色、焦点环用焦点色，深浅主题与沉浸状态共用这些 token，不另设色号；高度与栏顶相同，窗口全屏与屏幕全屏时随栏顶移出画面。
- 隐藏侧栏仍保留任务/录音状态和停止入口；标签、分屏与上下文切换不改变异步任务目标，不丢已确认保存的内容。
- 来源、实时引用、快照和复制有可识别行为；缺失引用保留描述与恢复入口。

## 3. 可访问性与中文输入

核心流程提供键盘路径、可见焦点、浮层退出和焦点恢复；颜色不是唯一提示。沿用交互设计的正文对比度目标，实际检查状态组合。输入法组合期间不能提交、触发全局快捷键或被 AI 更新覆盖。

窄窗按实际可用宽度折叠/抽屉处理，主要操作必须可达；检查高 DPI、文字缩放、长标题、空数据和长错误。减少动态效果偏好生效；阅读内容避免因后台进度更新反复跳动。

A-37 的双模式壳已由 A-94 取代，现在的壳只有一个工作区（交互设计第 2 节）。精确值由 `apps/desktop/src/renderer/styles.css` 单源维护；已有阅读主题另行管理。动画演示的静帧、模拟控制、预设对话和临时笔记必须始终可识别，不把演示效果写为正式媒体支持；范围见 [交互设计 3.3](../design/interaction-and-workflows.md#33-首版界面切片)。窗口框架的颜色、分隔线与阴影由 `styles-frame.css` 的 token 管理，窗口观察 `frame-flat-chrome`、`workspace-frame` 核对它们的位置与命中。

有 UI 实现后，报告标明应用版本/快照、平台、视口、缩放、主题、样本和实际检查步骤；截图须对应本次最终内容，必要时包括正常和关键失败状态。静态 HTML/设计图能验证布局设想，不能替代 Electron 的真实键盘、输入法、保存和任务流程。
