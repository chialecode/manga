# 应用外壳契约

| 项 | 值 |
|---|---|
| 状态 | authoritative |
| 落地阶段 | **阶段 3**（M3.0，先于媒体库界面） |
| 约束范围 | 阶段 3 之后所有涉及界面的工作 |

本文件定死**结构**：三栏几何、状态机、已打开资源的数据模型、面板注册机制、主题与字体的令牌契约。
**视觉细则**（精确色值、组件规格、间距表）在阶段 3 的 `DESIGN.md` 定稿，本文件只给方向与不可动摇的约束。

为什么结构必须现在定：`open_session.view_state` 与 `AsidePanel` 注册机制会被阶段 4（漫画）、阶段 5（小说）、阶段 6（视频）、阶段 7（证据）、阶段 8（AI）逐个消费。晚定一天，后面每个内核都要返工一次。

## 1. 三栏几何

```
┌────────┬────────────────────────────────────┬──────────┐
│  Rail  │              Main                  │  Aside   │
│  左栏   │             主面板                  │  右栏     │
│        │                                    │          │
│ 模式    │   媒体库 / 阅读 / 观看 / 撰写        │ 证据/AI/  │
│ 资源库  │                                    │ 录音/书签 │
│ 已打开  │                                    │          │
└────────┴────────────────────────────────────┴──────────┘
   ↑ 1px Board 分隔                    1px Board 分隔 ↑
```

整窗**单一平底色**，三区之间只用 1px 分隔线划分，**禁止用底色差区分区域**。抬起感只属于浮层（对话框、菜单、输入框），不属于页面结构。

| 区 | 默认宽 | 可拖拽范围 | 状态 |
|---|---|---|---|
| Rail | 240px | 200–360px | `expanded` / `icon` / `hidden` |
| Main | 剩余全部 | — | 始终存在 |
| Aside | 320px | 280–480px | `open` / `closed` |

窗口最小 **800 × 600**（与 `BrowserWindow` 的下限一致）。

## 2. 状态机

### 2.1 左栏三态

| 态 | 行为 |
|---|---|
| `expanded` | 240px，图标 + 文字 + 分组标题 |
| `icon` | **56px 纯图标栏**。hover 图标弹出浮层显示该分组内容，浮层不挤压主面板 |
| `hidden` | 宽度 0，仅在专注模式下进入，用户不能手动进入 |

`icon` 态下「已打开资源」显示为缩略图标堆叠，当前活动项有 accent 指示条。

### 2.2 右栏两态

| 态 | 行为 |
|---|---|
| `open` | 320px，并排 |
| `closed` | **宽度 0，无残留把手、无边缘条**。这是「需要能完全隐藏」的字面实现 |

`closed` 时唯一的唤出方式是快捷键与主面板工具栏上的按钮。**禁止**在窗口边缘留一条永久可见的把手 —— 那不叫完全隐藏。

### 2.3 专注模式

阅读与观看时的主状态，不是附加功能。

- 两栏同时归零，主面板占满整窗
- 鼠标移入窗口边缘 8px 内，对应侧栏以**浮层**临时出现，移开 400ms 后自动收回
- `Esc` 退出专注模式，恢复进入前的两栏状态
- 进入/退出有 ≤150ms 的宽度过渡；**禁止**位移、弹跳、缩放类动画

专注模式的状态**按资源类型记忆**：用户在漫画里习惯专注、在媒体库里习惯三栏，两者互不干扰。

### 2.4 窄窗降级

窗口宽度 < 1000px 时，右栏自动从「并排」转为「覆盖主面板的浮层」，主面板不再被挤压。这是自动行为，不写进用户设置。

## 3. 左栏结构

自上而下三段，顺序固定：

### 3.1 模式切换

爱好者 / 创作者。**两种模式是同一份数据上的两个工作台**，关系类比「消费」与「生产」：

| | 爱好者 | 创作者 |
|---|---|---|
| 用户在做什么 | 看，以及顺手记下来 | 把记下来的东西组织成产出 |
| 主面板承载 | 小说 / 漫画 / 动漫的阅读与观看 | 无限画布、思维导图、视频粗剪、文案撰写、灵感分析、资料搜集 |
| 左栏「资源库」段 | 按媒体类型分区 | 按产出物与素材分区 |
| 右栏面板 | 标记、书签、录音、AI | AI、证据检索、素材篮 |

**关键结论：模式切换换掉的是整个主面板的类型空间，不只是左栏分区。** 爱好者模式里不存在画布，创作者模式里不存在阅读器 —— 不是隐藏入口，是主面板根本不承载那类内核。

它**不改变**：库范围、文件访问权限、锚点与笔记的可见性。同一份库、同一批证据，两种模式都能完整访问。创作者模式的价值恰恰在于能取用爱好者模式积累的全部记录。

**切换必须是廉价且非破坏的**：两种模式各自保留自己的「已打开」列表与活动项，来回切换不丢状态、不重新加载、不弹确认。

持久化在应用设置中，不进路由、不进 URL。

> 「创作者模式下隐藏某些库」若将来需要，那是**库级开关**，不是模式的职责。不要把两件事混进一个开关。

### 3.2 资源库

按类型分区：全部 / 小说 / 漫画 / 动漫 / 标签 / 最近。分区列表由模式决定，不硬编码在组件里。

### 3.3 已打开

当前会话中打开的资源。可关闭、可拖拽排序、**跨重启恢复**。

## 4. 已打开资源 = 数据模型

「当前打开的资源列表」不是标签栏的视觉，它是一张表加一份内核契约。

```sql
CREATE TABLE open_session (
  id          INTEGER PRIMARY KEY,
  mode        TEXT    NOT NULL CHECK (mode IN ('fan','creator')),
  kind        TEXT    NOT NULL,
  -- 爱好者：指向具体文件；创作者：产出物自身，file_id 为 NULL
  file_id     INTEGER REFERENCES file(id)  ON DELETE CASCADE,
  work_id     INTEGER REFERENCES work(id)  ON DELETE SET NULL,
  artifact_id INTEGER,                      -- 创作者产出物 id，阶段 11 建表后加外键
  ord         INTEGER NOT NULL,
  active      INTEGER NOT NULL DEFAULT 0,
  view_state  TEXT    NOT NULL,             -- JSON，由各内核定义
  opened_at   INTEGER NOT NULL,
  touched_at  INTEGER NOT NULL,
  CHECK (
    (mode = 'fan'     AND file_id IS NOT NULL AND kind IN ('novel','manga','video'))
 OR (mode = 'creator' AND kind IN ('canvas','mindmap','timeline','document','research'))
  )
);
CREATE UNIQUE INDEX idx_open_session_fan ON open_session(file_id) WHERE mode = 'fan';
-- 每种模式各有且仅有一个活动项
CREATE UNIQUE INDEX idx_open_session_active ON open_session(mode) WHERE active = 1;
```

**`mode` 列是模式切换非破坏的实现基础**：切换模式只是换一个 `mode` 过滤条件，两边的列表与活动项各自独立存活。

创作者模式的产出物表（`canvas` / `mindmap` / `timeline` / `document`）在阶段 11 建立。**阶段 3 只建 `open_session` 这一张表并预留 `artifact_id` 列，不提前建产出物表** —— 那些字段现在无法确定，提前建只会产生错误的抽象。

### 4.1 内核契约（阶段 3 冻结）

每个主面板内核**必须**实现：

```ts
type FanKind     = 'novel' | 'manga' | 'video'
type CreatorKind = 'canvas' | 'mindmap' | 'timeline' | 'document' | 'research'
type MainKind    = FanKind | CreatorKind

interface MainKernel<TState> {
  readonly kind: MainKind
  readonly mode: 'fan' | 'creator'
  /** 序列化当前视图状态，写入 open_session.view_state */
  serializeViewState(): TState
  /** 从持久化状态恢复。状态不合法时必须降级到默认视图，禁止抛出 */
  restoreViewState(state: unknown): void
  /** 专注模式下是否允许边缘唤出侧栏（视频全屏时为 false） */
  readonly allowsEdgeReveal: boolean
}
```

`view_state` 的内容由各内核自定：

| 模式 | 内核 | view_state 内容 | 阶段 |
|---|---|---|---|
| 爱好者 | 小说 | CFI 或章节 + 偏移、字号、行距、主题、分栏数、竖排开关 | 5 |
| 爱好者 | 漫画 | 页码、缩放、适应模式、阅读方向、单双页 | 4 |
| 爱好者 | 视频 | `positionMs`、音轨 id、字幕槽 0/1 的轨道 id 与偏移、倍速 | 6 |
| 创作者 | 画布 / 思维导图 / 时间线 / 文案 / 资料 | 视口、选区、折叠态等 | 11 |

**`restoreViewState` 收到损坏或来自旧版本的状态时必须静默降级到默认视图**，不得抛出、不得清空 `open_session` 行。这条与锚点的失效语义同源：结构可以坏，记录不能丢。

### 4.2 与阅读进度的关系

`open_session.view_state` 是**会话态**（我上次在哪、用什么设置看的）。
阅读进度是**持久态**（这本书我读到哪了），存在各自的进度表里。

关闭资源会删除 `open_session` 行，**不影响**阅读进度。这是两件事，不要合表。

## 5. 右栏 = 面板槽

阶段 3 交付**机制**，不交付任何面板。

```ts
interface AsidePanel {
  readonly id: string
  readonly titleKey: MessageKey
  readonly icon: IconName
  /** 该面板在哪些模式下可用 */
  readonly modes: readonly ('fan' | 'creator')[]
  /** 该面板对哪些主面板类型可用；空数组 = 全部 */
  readonly contexts: readonly MainKind[]
  render(ctx: AsideContext): ReactNode
}
```

面板由后续阶段自行注册：

| 面板 | 可用模式 | 注册阶段 |
|---|---|---|
| 标记 / 书签 | 爱好者 | 7 |
| 录音 | 爱好者 | 7 |
| AI Agent | 两者 | 8 |
| 证据检索 | 创作者 | 11 |
| 素材篮 | 创作者 | 11 |

**阶段 3 的右栏是空的，这是正确状态。禁止为了「看起来完整」造占位面板。** 空态显示一行说明文字即可。

面板不可用（当前模式或当前主面板类型不匹配）时**从标签条中消失**，不显示为禁用态。

## 6. 主题令牌

### 6.1 三层结构

| 角色 | 用途 |
|---|---|
| `--surface` | 页面底色，整窗单一平色 |
| `--surface-elevated` | 抬起层：对话框、菜单、浮层、输入框 |
| `--border-default` | 1px 分隔线与容器描边 |

配色方向：**白为底，灰为结构，粉为唯一强调**。

- **白**：`--surface` 与 `--surface-elevated` 的浅色一族
- **灰**：分隔线、次级/三级文本、禁用态、图标默认色
- **粉**：`--accent`，**只用于**选中态、焦点环、进度指示、当前阅读位置、未读徽标

**禁止把粉用作大面积底色或容器填充。** 它是信号，不是装饰。

深色模式是交付门槛的一部分，不是可选项：任何界面变更必须同时完成两套模式，只做一套算未完成。

### 6.2 语义色白名单

除 `--accent` 外，只允许四个语义色：`success` / `warning` / `error` / `info`。
新增语义色必须先改本表，再进组件。

### 6.3 阅读区主题与 chrome 主题正交

这是本产品与工具类应用最大的差异。阅读与观看区有**自己的**底色集合，独立于 chrome 的明暗：

| 阅读主题 | 用途 |
|---|---|
| 纸白 | 白天、强光环境 |
| 护眼 | 长时间连续阅读 |
| 夜间 | 暗环境 |

用户可以在 chrome 为深色时用纸白阅读，反之亦然。两套主题各自持久化。

### 6.4 令牌纪律

组件中**禁止出现任何 hex / rgba 字面量**，一律走令牌。此约束由 CI 闸门在阶段 3 接线时一并建立。

## 7. 字体

### 7.1 字体栈

```css
--font-ui:          "Inter", "HarmonyOS Sans SC", "Noto Sans JP", system-ui, sans-serif;
--font-read-sans:   "HarmonyOS Sans SC", "Noto Sans JP", "Inter", sans-serif;
--font-read-serif:  "Noto Serif SC", "Noto Serif JP", Georgia, serif;
--font-mono:        "JetBrains Mono", ui-monospace, Consolas, monospace;
```

四条规则：

1. **UI 用 Inter 单一无衬线。** 层级靠字号与字重，不靠切换字体。
2. **中文与日文必须分别回退。** HarmonyOS Sans SC 不含日文假名与和字，日文内容必须落到 Noto Sans JP。本产品同时服务中日文内容，这一条不能省。
3. **长文阅读默认衬线。** 小说是长时间连续阅读，衬线在这个场景优于无衬线。用户可切换为 `--font-read-sans`。
4. **等宽只用于代码。** 不进 UI chrome。

字体以 webfont 形式随包分发，**不依赖用户系统已装字体**，否则中日文混排的回退结果在不同机器上不可预测。

### 7.2 字重阶梯（四档，禁止中间值）

| 档 | 用途 |
|---|---|
| 400 | 长文正文、代码 |
| 500 | UI 默认强调、标题 —— chrome 主力档 |
| 600 | 限量强调。新增使用要能说出「为什么 500 不够」 |
| 700 | 仅限 Markdown 渲染的 `**` 与品牌画布，**禁止出现在 UI chrome** |

**CJK 硬约束**：中日文回退字体的公开字重档位有限，UI 中使用 700 会触发伪粗体（算法加粗、边缘发糊），且 600 与 700 在 CJK 上的渲染差异不可靠。
**中日文层级不得依赖 600 与 700 的区分，强调改用字号或颜色。**

### 7.3 字号

UI 段：`{11, 12, 13, 14, 15, 16}`px。标题/内容段：`{18, 20, 24, 28}`px。下限 11px。

白名单约束的是**开发者写死的档位**，不约束运行期缩放结果。

**阅读区正文字号不在白名单内** —— 它是用户设置项，12–32px 连续可调。

## 8. 几何

### 8.1 圆角三档

`8px`（内层控件：多行输入、菜单行高亮）/ `12px`（容器：卡片、面板、对话框、封面卡）/ `9999px`（胶囊：按钮、标签、单行输入、徽标）。

**不存在第四档。** 内层圆角必须小于其容器圆角，否则嵌套会顶边。

### 8.2 间距

基数 8px。可用刻度：`4, 6, 8, 12, 16, 20, 24, 32, 40, 48`。

### 8.3 阴影

**基础语言零阴影。** 深度来自 1px 分隔线与底色差。
唯一例外是脱离文档流的浮层（菜单、命令面板、对话框），使用令牌化的单一阴影值。禁止给页内元素临时加阴影。

## 9. 键盘与无障碍

- 所有交互元素可键盘到达，焦点环使用 `--accent`，且在两种模式下对比度均达标
- 左栏折叠、右栏开关、专注模式各有独立快捷键，可在设置中改
- 焦点陷阱、ARIA 语义、层叠管理由无障碍原语库提供，不自研
- 对话框打开时焦点落在主输入或主按钮上，**不落在取消**

## 11. 对启动基准的影响

阶段 1 的 E5（空应用窗口可见 P95 ≤ 1.2 s）测的是空白页。外壳落地后，webfont 加载与首屏 CSS 会进入启动路径。

**阶段 3 必须重测启动基准并更新 `docs/bench/` 的基线**，否则 1.2 s 这个数字会失真。字体分片与首屏关键 CSS 内联的取舍在那时决定。
